# Changelog

All notable changes to PHANTOM are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added — extracted image preview in Tauri Desktop

- Detect JPEG and PNG by contents, show file type, name and size, and open an
  in-app aspect-preserving preview with Escape to close. The original is saved
  unchanged via the verified extraction path.
- The in-memory preview accepts at most 8 MiB and 20 million input pixels,
  downsizes to 1024 pixels per edge and caps the encoded copy at 1 MiB. Large,
  corrupt and unsupported files can still be saved without a preview.

### Added — long text editing and reading

- Expand the text editor or extracted text into the application workspace,
  collapse with the button or Escape, keeping paragraphs and draft in memory.
- Oversized extracted text is identified as unavailable for preview and can
  still be saved as TXT through the verified bridge writer.

### Fixed — protect the carrier during extraction

- Refuse to save extracted content over the original carrier, including aliases
  to the same file, and explain how to choose another location.

### Fixed — verified extraction and password copy

- Extracted files now use the core's owner-only atomic verified writer with the
  extracted SHA-256, preserving any existing destination on verification failure.
- The password field has an explicit copy button; confirmation appears only
  after a successful clipboard write. The clipboard is not cleared by a timer.

### Fixed — native file picker payload size

- Map Rust's `size_bytes` to React's `sizeBytes` and reject invalid or missing
  sizes without treating them as zero. Explain the problem beside the file and
  offer reselection; do not calculate capacity until the size is known.
- Exercise real native response shapes, including oversized and invalid sizes,
  in the Hide screen regression tests.

### Fixed — macOS packaging: nested code signed before the .app, dmg packed last

The bundle shipped by the previous pipeline could not be verified
(`code has no resources but signature indicates they must be present` when
checked on a stock MacBook).  The `build-macos` job now: (1) builds the
`.app` only, (2) records the pre-fix signature state for the report,
(3) ad-hoc signs the nested `phantom-bridge`, then the whole `.app`
(`codesign --force --deep --sign -`), (4) gates on
`codesign --verify --deep --strict --verbose=2` for both the built bundle
and the same bundle re-checked from the mounted `.dmg` — CI fails if the
check fails; (5) creates the `.dmg` after signing and (6) includes the image
SHA-256 and verification output in the artifact. Diagnostic artifacts can still
be uploaded on failure; the job remains failed.  Ad-hoc only: no Developer ID, no notarization.

### Fixed — desktop prototype (Tauri 2 + React/TypeScript), review round 2

- Carrier gate: while no carrier is chosen the Hide screen shows the hint
  "Choose a picture or audio" («Выберите картинку или аудио» /
  «Оберіть картинку або аудіо») in place of the capacity gauge; the
  "does not fit" banner can only appear after the selected carrier has been
  probed (component tests + CI layout check).
- The primary action button is guaranteed fully visible at 980×720 in file and
  text mode, light and dark themes — layout reworked and now enforced by
  `desktop/e2e/layout_check.mjs` in CI (not just eyeballed screenshots).
- Draft semantics: screens stay mounted (hidden only), so text typed or a
  file picked survives navigating to Settings and switching language.  Only
  language and theme are persisted; passwords and document contents live in
  memory and are never written to storage (`App.test.tsx` pins this,
  key by key).


### Added — desktop prototype (Tauri 2 + React/TypeScript)

- **`desktop/` — a second, modern shell for the existing Python core.** Same
  algorithms, same container format, same `phantom.core.api` calls, wrapped in a
  Tauri 2 window (React 18 + TypeScript, 980×720) that targets macOS arm64,
  Windows x64 and Linux without a Tk dependency.
- **Stage one is one finished scenario: hide a PDF in a PNG, extract it back.**
  The screen opens with «Что хотите спрятать?» — file, text or a bundled example
  (`example_payload.pdf`, new, 809 bytes, regenerated by `tools/make_example_pdf.py`)
  — then offers a PNG or WAV/FLAC carrier side by side («Что прячем» / «В чём
  прячем»), a system file picker, drag & drop, a live capacity bar, a password
  field with strength meter and generator, inline errors in Українська /
  English / Русский, and light/dark/system themes. Language and theme are chosen
  on first launch and change instantly in Settings, persisted as a local draft.
- **`src/phantom/bridge.py` — the stdio JSON contract between the shell and the
  core.** One request per line; passwords and payload bytes travel only on
  stdin, never on the command line or in logs; a frozen PyInstaller sidecar
  (`desktop/phantom-bridge.spec`) ships inside the bundle as Tauri's `externalBin`.
- **CI: `.github/workflows/desktop.yml`** builds the app on macos-14 (arm64),
  windows-latest (x64) and ubuntu-24.04 (x64), then runs the stage scenario
  (`desktop/e2e/full_cycle.py` — hide, extract, byte-compare SHA-256) twice per
  OS: against the freshly frozen bridge and against the bridge inside the built
  package. Screenshots of the real interface are captured on the web bundle at
  exactly 980×720.


- **A green run that verified nothing is now red.** `tools/ci_verdict.py` counted the
  rows in `ci/status.tsv`, so a step that was skipped — and therefore wrote no row —
  could not be told apart from one that passed: with every other row green and
  `gui suite (tk9)` absent, the verdict was 0. Mandatory steps are now named with
  `--require`, an absent one fails the job with its own name
  (`::error::missing: gui suite (tk9)`), and the Tk 9.1 job requires all five of its
  gate rows. `tests/test_repo.py` keeps each job's list equal to the gate rows it
  writes.


### Fixed

- **Empty PHANTOM frame and 3–5 s startup freeze on macOS Tk 9.1 Aqua.** On repeated
  launches from Terminal, `PhantomApp` constructed ~300 widgets inside a `CTk()` root
  that had never been `deiconify()`-ed; realizing all unmapped subviews at once on
  first event-loop entry (or on a post-build `deiconify()`) stalled Tk's event loop
  for 13.6–14.4 s on the macOS Tk 9.1 CI runner (3–5 s spinning wait cursor on M1
  Pro, with an empty frame until focus switched). `PhantomApp._configure_root()` now
  deiconifies a normal (non-withdrawn/non-iconified) root *before* building child
  widgets, and `refresh_window()` raises and focuses a normal window on macOS while
  preserving the active input focus and keeping `update_idletasks` permanently refused
  on Tk 9.1 (`DISPLAY_PASSES_UNSAFE`). Measured across 3 launches each on `gui-tk9`
  (run `44921032666`): `after(0)` entry dropped from 14.2–14.9 s to 0.52–1.06 s,
  worst loop gap dropped from 13.6–14.4 s to 0.44–0.63 s, `screencapture` first
  content appeared at 0.47–0.94 s without any focus push, «Метаданные» clicked in
  0.0–0.2 ms, and every window closed cleanly (`still_open=False`).
- **CI can no longer call a segmentation fault a success.** A step marked
  `continue-on-error: true` reports success whatever happened inside it: the runner
  still writes the annotation *Process completed with exit code 139*, and the run
  was green. Every step now records its own exit code and one step decides
  (`tools/ci_verdict.py`): a gate may not fail, a declared diagnostic may fail a
  test but may not die, a probe of an older tree may time out. Signals (`128 + N`),
  timeouts and "the command never started" fail the run; nothing is inferred from a
  green step. The layout profile is now a gate for this tree — it used to swallow a
  150-second timeout and a log without a `SUMMARY` line and stay green, and
  `profile_resize.py` now exits 3 instead of 0 when its watchdog ended the run.
- **A copy no longer claims more than the board can prove.** Tk's clipboard on Aqua
  re-encodes what it is given: in CI every emoji in a 37 800-character payload
  arrived in another application as four Latin-1 characters (`😀` → `ðŸ˜€`), and 7 of
  24 300 characters differed in a smaller one. The window keeps Tk as the clipboard
  owner — a native write takes the claim away, which cost six window tests their
  clipboard in CI (stale strings, `CLIPBOARD selection doesn't exist`) — and reads
  the board back with both readers, Tk's own answer and the system's exact one, to
  decide what the footer says. A copy the pasteboard converted is reported as "not
  exact, use the file" instead of a transfer that did not happen. The system reader
  is asked only for the shapes the conversion was measured on — 4 096 characters or
  more, or a character outside the BMP — so a short password costs no subprocess.
  The TXT export keeps using the payload bytes and is unchanged;
  `tools/smoke_editor_capacity.py` prints both views so the difference stays
  measured.
- **What Tk does to non-ASCII is measured, gated and reported separately.** A
  260 000-character Cyrillic document came back from the pasteboard as Latin-1 and
  every emoji in a 37 800-character result became four characters: Tk converts on
  both sides of `NSPasteboard`, so a copied non-ASCII payload is not what another
  application pastes. The window asks the exact reader for the payload shapes where
  this was measured, and the footer says *"not exact — use the file"* instead of
  *"copied"*. `tools/smoke_editor_capacity.py` gates what PHANTOM controls (the
  window's own value, byte for byte) and prints the conversion as a `note` with the
  diff, counted in its `SUMMARY`.
- **A failing step no longer loses the record of its own exit code.** GitHub runs
  every `run:` block with `bash -e -o pipefail`, so the GUI job's `ci/status.tsv` was
  never created (verdict exit 2) and the Tk 9.1 job's two *failing* steps were the
  two rows missing from its table: the shell stopped before the line that records
  the code. Recording steps now start with `set +e`, the verdict prints every row as
  an annotation, and an invariant test fails the suite if a new step forgets.
- **The layout profile says what it measured.** On the macOS runner
  `-fullscreen True` never returns: the callbacks behind it never run and the tool's
  own watchdog cannot fire, so the run ended at the 150-second cap with no `SUMMARY`
  line — and the job was green because that timeout was swallowed. `profile_resize.py`
  grew `--skip-fullscreen` for the gate run, and the phase is probed on its own where
  a stall is the finding. The runs after that kept timing out, and the reason was in
  the tool: the summary call passed `flush=True` to a one-argument `say`, so every run
  raised `TypeError` *inside a Tk callback*, which Tk prints and ignores — the loop
  kept turning, `SUMMARY` was never written and the job reported a timeout with no
  measurement. `say` takes the keyword now, `root.report_callback_exception` prints
  the traceback and exits non-zero so the next swallowed callback fails loudly,
  `finish()` prints the machine-readable line first and leaves with `os._exit`, and
  the step streams each child's output into its log (a capture returns only what it
  read when the timeout fires), gates on `SUMMARY` and gives a run that had to be
  killed after the numbers a `probe` row of its own.
- **The crash that leaves no traceback is readable now.** `tools/parse_crash_report.py`
  prints the faulting thread of a macOS `.ips` report with symbols, and
  `tools/diagnose_tk_crash.py` runs one candidate per process — bare Tk, CustomTkinter,
  tkdnd loaded, the real window with and without drag-and-drop, and the crashing
  test's own shape: a plain root, a provider that cannot register, one `update()`,
  plus three windows built and destroyed first — so a SIGSEGV costs one child and the
  table still prints. The lldb step now launches the variant that crashes and stops
  on `SIGSEGV`: it used to run the *theme smoke*, which passes, with
  `stop-on-exec false`, which is why `bt all` answered `Command requires a process
  which is currently stopped`.
- **The layout profile is a measurement again.** Three defects stood between the job
  and its numbers: a `TypeError` raised inside a Tk callback (Tk prints it and carries
  on, so `SUMMARY` was never written and the job timed out "without a measurement"), a
  capture that returned only the output it had read when a timeout fired, and a native
  fullscreen call that does not always return on a runner. The tool now prints its
  machine-readable line first, exits with the numbers, fails loudly on a callback that
  raises, and `--skip-fullscreen` keeps the phase out of the gate; the step streams
  each log and reads `SUMMARY`. On run `44852903515` the old tree costs 2.0 ms per
  resize handler and this branch 0.26 ms, with refit passes 130× cheaper.
- **The Tk 9.1 SIGSEGV has a name and a guard.** The macOS `.ips` report puts the
  fault inside Tk's own idle handler — `showRootWindow` ← `TclServiceIdle` ←
  `Tcl_DoOneEvent`, `KERN_INVALID_ADDRESS at 0x170` — with no PHANTOM,
  CustomTkinter or pytest frame in it. Tk's Aqua menu code arms an idle callback that
  points at the menu of the interpreter that armed it; every test that closes its
  window destroys an interpreter, and the next event-loop service runs the callback
  against freed memory. Measured in two processes: the crashing test alone is green
  (1 passed, 172 deselected), the suite without it still dies with 139. The
  application opens one interpreter per process and is not exposed. Two guards, both
  measured: the availability probe in `tests/test_gui.py` no longer destroys the
  `tkinter.Tk()` it opens (a second report shows the same handler sending an
  Objective-C message to a deallocated window: `objc_opt_respondsToSelector` ←
  `Tk_MacOSXGetTkWindow` ← `showRootWindow` ← `TclServiceIdle`), and the Tk 9.1 job
  runs the suite in one process per test — chunks of eight were tried first and four
  of twenty-two still died. Every test still runs, every chunk must pass, a crash
  still fails the job, and the Tk 8.6 job keeps the whole suite in one process. The
  crash report and the diagnosis table are annotated on every run instead of only
  being written to a step log.
- **`PHANTOM_DND=0` turns drag-and-drop off before anything is imported.** The switch
  exists for a machine where the Tk build cannot survive the tkdnd library, and the
  crash diagnosis uses it to tell the window apart from the window plus tkdnd.

- **The red «ОШИБКА» now has a reason and a next step.** The footer used to print
  a bare `ОШИБКА` in two situations: a cancellation (`_show_error` returned before
  the dialogue), and a failed event handler, which only wrote a log line — so the
  window said it had failed and nothing on screen said why. Every error path now
  carries its reason (`status_error_detail` = `ОШИБКА: …`), a cancellation is
  reported as `ОТМЕНЕНО`, a failed handler names the step it was on and says the
  files on disk were not touched, and a failed integrity check on extracted data
  says the data must not be saved instead of reusing the word "error".
- **The expanded result window copied a truncated string.** `РАЗВЕРНУТЬ` read the
  small panel *widget*, which holds an extraction preview; with a large text the
  window then showed and copied only the beginning. It now takes the whole
  payload from the model, and its own pane is capped for painting only — copying
  and saving always use the complete text.
- **A payload that is not valid UTF-8 was silently "repaired" on screen.** The
  result pane decoded with `errors="replace"`, so a damaged payload appeared with
  U+FFFD characters — text that looked extracted and was wrong. Decoding is now
  strict: either the payload is text and is shown exactly, or the window says it
  cannot be shown as text, points at the file path, and leaves the bytes alone.
  Nothing is ever rewritten to make it decode.
- **`СИСТЕМА ГОТОВА` while the payload no longer fits.** The footer kept its idle
  text over an exceeded capacity, and kept a finished verdict (`СОХРАНЕНО → …`)
  after the text had changed. A finished status is now cleared when the payload
  changes, and the footer says `ПРЕВЫШЕНА ЁМКОСТЬ — ЗАШИФРОВАТЬ НЕЛЬЗЯ` whenever
  the panel does.
- **The editor no longer reads the whole field on every keystroke.** Each edit
  used to pull the text out of Tk, count characters, count UTF-8 bytes and scan
  every line — four full walks of a multi-megabyte string per keystroke. A
  keystroke now only marks the field dirty; one debounced commit reads the field
  once and measures it once (`phantom.core.text.measure_text`: 6.6 M characters,
  381 000 lines, 92 ms with the line scan and 10 ms without), and every counter,
  the wrap decision and the size estimate use that snapshot.
- **Undo is bounded, and a full reset leaves nothing to undo.** Tk keeps the text
  every undo step changed, and the history was unbounded (`maxundo=-1`). It is now
  capped by `C.EDITOR_MAX_UNDO`; `СБРОС` additionally drops the history
  (`edit_reset`) and the application-held references to the payload and to the
  generated password. Emptying the field with `ОЧИСТИТЬ ПОЛЕ` stays an ordinary
  undoable edit. This is a release of references, not a claim of physical
  erasure — see `SECURITY.md`.

- **The payload field takes a large paste, and says how big it is.** Three
  separate faults looked like one. Select-all left the caret *in front of* the
  selection, so the next keystroke prepended text instead of replacing it, and
  the tag was never raised above the text tags — on Aqua the highlight was
  invisible. Tk's undo history was never switched on, so `Cmd+Z` did nothing at
  all. And nothing told the model that the text had changed unless the widget
  both saw a key press *and* its release: a paste whose release was routed
  elsewhere left the counters and the size estimate describing the previous
  text. The editor now listens to Tk's `<<Modified>>` flag (one edit, one
  refresh), raises and re-anchors the selection like a native field,
  enables the undo stack, and drives undo/redo from `Cmd+Z`,
  `Cmd+Shift+Z`, `Ctrl+Z`, `Ctrl+Y` and `Ctrl+Shift+Z`. Measured on
  Tk 8.6.16 in CI: 260 000 characters pasted by a real `Cmd+V` insert in
  11–56 ms, and the whole clipboard arrives.
- **A single enormous line no longer freezes the window.** Tk lays a line out
  for display, and word wrap on one line costs seconds: the same 260 000
  characters took 29 ms broken into document lines against 13.6 s as one
  120 000-character line (8.6.16) and 75 s as one 260 000-character line
  (9.1.0). Above `EDITOR_WRAP_LINE_LIMIT` (20 000 characters on one line) the
  editor switches to `wrap="none"` and a hint under the counters says so. The
  text itself is never split, trimmed or truncated; wrapping returns as soon as
  no line is that long.
- **Selecting all and copying work from the context menu too.** Every editing
  command is one handler shared by the keystroke, the virtual event
  (`<<Paste>>`, `<<Copy>>`, `<<Cut>>`, `<<SelectAll>>`, `<<Undo>>`, `<<Redo>>`)
  and the menu, and each returns `"break"`, so a class binding cannot run the
  command a second time.

### Added

- **An action bar under the payload field**: paste, copy, cut, select all, undo,
  redo, copy all and clear field. Every button calls the same handler as the
  hotkey and the context-menu entry (the bar holds the very
  `ClipboardActions` object the shortcuts use), so a button cannot drift from
  `Cmd+C`. Availability follows the editor: copy needs a selection, copy all
  needs text, undo/redo follow what the window has seen, and everything is
  disabled while a job runs or in file mode.
- **Result actions**: `ВЫДЕЛИТЬ ВСЁ`, `КОПИРОВАТЬ ВЫДЕЛЕННОЕ`,
  `КОПИРОВАТЬ ВСЁ` and `СОХРАНИТЬ TXT (UTF-8)`. Copy-all and the TXT export work
  from the model, not from the pane: the export writes the decrypted bytes
  verbatim and verifies them against the payload's SHA-256, so nothing is
  normalised (NFC/NFD), no character is replaced and no line ending is rewritten.
  The read-only result field binds `Cmd/Ctrl + A` and `Cmd/Ctrl + C` and no
  longer offers paste, cut or undo in its menu, which could only fail there.
- **`tools/profile_editor_capacity.py`** measures the real window at
  100 KiB … 15 MiB for multiline, single-long-line and mixed-Unicode payloads:
  Tk `insert`/`get`/`delete`, select-all, the counting, the clipboard round trip,
  undo/redo, the commit path, the longest interval in which the Tk loop did not
  run at all, peak RSS, and the memory left after a field clear and a full reset.
  It prints one markdown table.

- **`ОЧИСТИТЬ ПОЛЕ` next to the counters.** It empties the payload field, the
  model, the estimate and the counters, returns the caret to the field and
  aborts the pending estimate. It does **not** touch the password, the carrier,
  the output path, the payload mode or any setting — the tab-wide `СБРОС`
  keeps doing that. The same command is in the editor's context menu, and
  `Cmd+Z` after it brings the text back.
- **A capacity panel, built from the numbers the engine already computes.** It
  shows the container (name, format, on-disk size, resolution/mode or
  duration/sample rate/bit depth/channels), the payload (characters, UTF-8
  bytes, prepared size — compression plus header — from the estimate), and the
  capacity (available, occupied, free, percent, and the excess when there is
  one) on **one** scale: `SizeEstimate.payload_bytes` against
  `Capacity.payload_bytes`, so nothing is counted twice. The fill bar stays
  capped at 100 % while the number may pass it. The states are explicit — no
  carrier, no payload, calculating, fits, does not fit, calculation error — and
  the panel says in one line that the estimate is preliminary, that the engine's
  own final check is what decides, and that capacity is measured in payload
  bytes, not in the file size on disk.
- **Embedding is blocked while the numbers are unknown or do not fit.** Over
  capacity keeps every character, shows how much is missing and how much the
  carrier really holds instead of letting the engine's final check refuse the
  job. Each estimate carries the revision it was started for; a result for older
  text or another carrier is dropped and re-measured rather than shown against
  the text on screen.
- **The window fits its own text at every size and in every language.**
  CustomTkinter keeps the width a button was created with, so
  «ВЫБРАТЬ ФАЙЛ (PNG / WAV / FLAC)» was clipped on both sides in a windowed
  window. Nothing resizes the minimum window or shrinks a font: every caption is
  measured in its own font, `width=` became a minimum instead of a cap, a row of
  buttons wraps onto a second line when it does not fit, and `wraplength` follows
  the card. The GUI suite measures every captioned widget against its own text at
  980×720, 1140×900, 1280×800, 1440×900 and after each language switch.
- **Start-up is measured and shorter.** `PHANTOM_STARTUP_DEBUG=1` prints per-stage
  timings (import, Tk root, each tab, the render passes, the first frame, the
  moment the window is on screen) and a summary line. Three costs went away: the
  system font list was enumerated once per widget (now once per window, with the
  fonts cached), the saved geometry was applied *after* building all four tabs
  (now before, so the window is laid out once), and the metadata panel was
  rendered twice in the same tick (now once). Housekeeping that the first frame
  does not need runs on the first idle callback.
- **Scroll chaining.** A multi-line text box keeps the wheel while it can still
  move the way the gesture asks; an empty box, one whose content is fully visible
  or one at its last line hands the same event to the page, so scrolling no longer
  stops over a text field. One gesture is answered once, even though the router is
  now also bound on the text widgets themselves (Tk's class binding could
  otherwise consume the event before the global handler saw it).
- **The metadata tab explains itself**: the plan of the next operation and the
  result of the previous one are separate cards; the save button is disabled (with
  the reason) when nothing is selected or the clean is blocked; a reset button
  clears the file and the results; the verdict is coloured and shows the field
  count before and after; the full SHA-256 values can be copied; protected rows are
  dimmed with their reason; «Очистка не требуется» replaces an empty plan; the
  reveal button names the system's file manager (Finder / Проводник); and the TXT
  report, like every status line, follows the window language while the JSON export
  stays English and versioned.

### Changed

- **The result pane paints at most `C.RESULT_PREVIEW_CHARS` (200 000) characters**
  and says so in a caption; a 15 MiB insert into a Tk text widget is a
  multi-second display pass on Aqua. The payload is untouched: copy-all, the TXT
  export and the expanded window all use the complete text. No data is truncated
  anywhere, only painted.
- **The clipboard auto-clear stays a password-sized promise.** Deciding whether a
  15 MiB clipboard is still ours means reading it all back on the GUI thread, so
  values above `C.CLIPBOARD_AUTO_CLEAR_MAX_CHARS` are not armed for the 30-second
  clear — and copying more than `C.CLIPBOARD_EXACT_WARN_CHARS` characters says in
  the footer that the pasteboard may not hand back an identical string, pointing at
  the TXT path instead of promising something the application cannot check.
- **A theme or language switch no longer re-paints the result preview.** The pane
  remembers which payload it shows and stays put when nothing new arrived.

- **Start-up work that nobody sees.** CustomTkinter's scrollbar flushes the whole
  window on every draw, and the build draws about a hundred of them — each flush
  paying for everything laid out before it. The build and the first render now run
  with that flush off and end with one, which is the same answer for every
  scrollbar at once. Sizing a caption no longer redraws a widget that is not on
  screen yet: during the build the width a widget already has is a floor, and only
  a longer caption widens it. `tools/bench_startup.py` measures the result (median
  of three full builds, with `--profile` and `--stages` for the detail), and the CI
  GUI job runs it for this branch and for its base and reports both.
- The collector is restored to the state it was found in: a job no longer enables
  a collector that was already disabled, a resume is refused while another job
  owns the pause, and a failing poll callback is logged and re-armed instead of
  wedging the window.

- **Long operations now say what they are doing.** With v5 as the default a 24 MP
  photo takes about half a minute to embed, and the interface used to show a
  progress bar frozen at 0 % for the first stretch of it — indistinguishable from
  a hang. Four changes fix that:

  * a new `Stage.ANALYSING` for the wavelet cost map, the one phase that cannot
    report a fraction (it is a single opaque pass over the image). `Stage` values
    double as locale keys, so it is named in all three languages, and it joins
    `Stage.KDF` in `INDETERMINATE_STAGES` — the interface already knew how to show
    a spinner for those, it just had nothing to spin for;
  * the engine announces it before the cost map is computed (both for the v5
    trellis and for the v4 greedy layout) and only when the carrier is an opaque
    image, so audio and transparent-pixel carriers do not claim an analysis they
    never run;
  * `_read_stc_payload` reports every block chunk instead of only the endpoints:
    extracting a 24 MP file used to sit at 0 % for ten seconds and then jump to
    100 %;
  * the footer carries an elapsed-time counter (`C.STAGE_TICK_MS`, one repaint per
    second), so a phase that reports nothing still visibly moves. It stops and
    resets when the operation ends — including on cancel and failure, which used
    to leave the last "embedding · 74 %" line on screen forever — and a language
    switch mid-operation repaints the live line in the new language rather than
    reverting it to "idle".

  The line itself is built by `ui.format.stage_line`, which is free of Tk, so the
  wording is covered by the headless tests; the tests also pin that the clock is a
  suffix (`Встраивание  ·  25% · 12 с`), that an indeterminate phase never shows a
  percentage, and that a stuck phase keeps counting past a minute without changing
  units.

- **`SECURITY.md` states the price of the half-resolution cost map** — 0.25 dB at
  0.2 bpp, 0.18 dB at 0.4 bpp, measured against the exact map — instead of leaving
  it in the CHANGELOG only. The READMEs mention the trade-off and the new progress
  feedback.

- **Experimental syndrome-trellis layout (v5).** The adaptive layout picked the
  cheapest samples and wrote one bit into each — greedy, and blind to the fact
  that one ±1 change can satisfy several parity constraints at once. The new
  `phantom.stego.stc` module embeds with a **syndrome-trellis code**: it looks for
  the change vector `e` that minimises the total distortion `Σ ρᵢeᵢ` subject to
  `H e = σ`, where `σ` is the syndrome carrying the payload. `Ĥ` is a
  `height × width` binary matrix placed block-wise on the diagonal, the trellis
  has `2**height` states holding the block's partial syndrome, and a Viterbi pass
  finds the shortest path; with `height ≤ 8` and blocks of 6–256 samples the whole
  thing runs as a handful of NumPy operations per layer, batched across every
  block at once. Each file uses the widest block it can afford, because a wider
  block carries a bit with fewer changes (`≈ 1 / log₂ width` per bit).

  `Ĥ` is derived from the password, so the syndromes cannot even be computed
  without it, and — unlike v4 — **nothing about extraction depends on the image**:
  the trellis comes from the carrier size, the payload length and the key, so the
  layout cannot drift and needs no verification, no mask invariant and no fallback
  check. `engine.embed_payload(..., container_version=5)` writes it, and since the
  change below it is what the build writes by default.

  Same eight carriers, same payloads, all three layouts, extraction verified on
  every file (`96 embeds in 142.7 s, 0 unreadable`). `Σρ/бит` is the total cost
  of the changes divided by the payload under one shared cover-derived map — the
  number a trellis is built to minimise:

  | load, bpp | layout | PSNR, dB | changed px, % | Σρ/bit | χ² p | RS p̂ | detected |
  |---|---|---|---|---|---|---|---|
  | 0.05 | v3 keyed | 68.93 | 2.48 | 0.50 | 0.000 | 0.012 | 0/6 |
  | 0.05 | v4 greedy | 68.95 | 2.38 | 0.46 | 0.000 | 0.024 | 0/6 |
  | 0.05 | **v5 trellis** | **72.82** | **1.01** | **0.19** | 0.000 | 0.012 | 0/6 |
  | 0.10 | v3 | 65.89 | 4.94 | 0.50 | 0.000 | 0.004 | 0/6 |
  | 0.10 | v4 | 65.92 | 4.72 | 0.46 | 0.000 | 0.037 | 0/6 |
  | 0.10 | **v5** | **70.27** | **1.80** | **0.17** | 0.000 | 0.011 | 0/6 |
  | 0.20 | v3 | 62.90 | 9.67 | 0.50 | 0.000 | 0.009 | 0/6 |
  | 0.20 | v4 | 62.91 | 9.26 | 0.46 | 0.000 | 0.063 | 0/6 +3 suspect |
  | 0.20 | **v5** | **67.35** | **3.51** | **0.17** | 0.000 | **0.008** | 0/6 |
  | 0.40 | v3 | 59.90 | 18.68 | 0.50 | 0.000 | 0.007 | 0/6 |
  | 0.40 | v4 | 59.90 | 17.61 | 0.47 | 0.000 | 0.085 | 0/6 +3 suspect |
  | 0.40 | **v5** | **63.25** | **8.74** | **0.22** | 0.000 | **0.010** | 0/6 |

  The code wins on every axis it can control: three to four decibels more PSNR,
  2–2.9× lower total distortion, 2–3× fewer changed samples, chi-square still at
  zero. The RS estimator — which reads the *density* of changes and had climbed to
  0.085 (three carriers in the "suspect" band) under greedy v4 — comes back to the
  v3 level, 0.008–0.012, and no carrier is flagged at any load. Spreading a
  smaller number of changes over the whole carrier beats concentrating a larger
  number in the cheapest corner, even though the greedy layout wins the placement
  columns (`перцентиль`, `в гладких 50%`): the cost model is additive and does not
  know that a dense cluster is easier to see than the same changes spread out.

  Limits, stated in the module: blocks are independent, so the optimum is
  per-block rather than global (the published trellis slides by one sample, which
  is hundreds of times slower in pure Python and buys a fraction of a percent);
  and the *number* of changes is public — only their placement is keyed.

- **Experimental adaptive layout (v4).** LSB matching spreads its changes
  blindly, and blind changes are what a texture-aware detector looks for. The new
  `phantom.stego.adaptive` module computes a cost map from the image itself — a
  two-level Daubechies-8 wavelet decomposition (db4, four vanishing moments, so a
  smooth gradient produces almost no response), the detail energy of the HL/LH/HH
  bands, a HILL-style spread over a 15×15 neighbourhood, and a cost of
  `1 / (energy + floor)` normalised to a median of 1 — and the payload goes to the
  cheapest samples: foliage, edges, noise, never the sky. Costs are log-quantised
  into six buckets, ordered inside each bucket by a password-derived permutation,
  so the layout is a function of the key and the image and never of the payload.
  `engine.embed_payload(..., container_version=4)` writes it; v3 remains the
  default and every existing file still opens.
  
  The one structural problem was reproducibility: the receiver has no cover, so
  it must rebuild the layout from the stego image, and a cost map computed after
  the embedding is not the same map (measured: 1–1255 positions drifted
  depending on bucket count, which corrupts the payload). The fix is a **mask
  invariant**: a change is written in the direction that keeps the sample inside
  its 16-value group (low nibble `0000` goes up, `1111` goes down, otherwise a
  keyed coin), so
  `value >> 4` never moves, the coarse image is identical on both sides, and the
  costs — computed from that coarse image — are provably identical. The engine
  still re-derives the layout after writing and falls back to v3 if it ever
  disagrees, but with the mask invariant it never does: 64/64 benchmark embeds
  reproduced themselves.
  
  Benchmarked with `tools/bench_steganalysis.py --layout both` on the same eight
  carriers at the same payload sizes (percentile = median cost percentile of the
  changed samples, 50 % = blind):

  | load, bpp | layout | PSNR, dB | changed px, % | percentile | smooth half | χ² p | RS p̂ | detected |
  |---|---|---|---|---|---|---|---|---|
  | 0.05 | v3 | 68.95 | 2.46 | 49.9 | 49.9 % | 0.000 | 0.009 | 0/6 |
  | 0.05 | v4 | 68.93 | 2.40 | 4.7 | 1.5 % | 0.000 | 0.025 | 0/6 |
  | 0.10 | v3 | 65.93 | 4.89 | 50.1 | 50.3 % | 0.000 | 0.005 | 0/6 |
  | 0.10 | v4 | 65.90 | 4.71 | 5.4 | 0.8 % | 0.000 | 0.040 | 0/6 +1 suspect |
  | 0.20 | v3 | 62.89 | 9.70 | 50.2 | 50.2 % | 0.000 | 0.011 | 0/6 |
  | 0.20 | v4 | 62.90 | 9.25 | 7.6 | 0.4 % | 0.000 | 0.071 | 0/6 +3 suspect |
  | 0.40 | v3 | 59.90 | 18.67 | 49.9 | 49.9 % | 0.000 | 0.024 | 0/6 |
  | 0.40 | v4 | 59.89 | 17.64 | 8.4 | 0.2 % | 0.000 | 0.088 | 0/6 +3 suspect |

  Distortion is identical, placement is not: v4 puts its changes in the cheapest
  tenth of the cost map and almost never in the smooth half, where v3 is at 50 %
  by construction. Chi-square stays at 0.000 for both. RS, an estimator built for
  LSB replacement and already known to wander on LSB matching, reads *higher* for
  v4 at 0.1–0.4 bpp (0.040–0.088 against 0.005–0.024): concentrating changes in
  the noisiest regions is exactly where its group model is least reliable, so the
  number has to be reported as it is, not as a win. Both stay far below the 0.25
  "flag" line, and no carrier was called detected.
  
  Limits, stated in the module: without syndrome-trellis codes the selection is a
  hard subset, so the *set* of touched samples is visible to a detector that knows
  the scheme; the masked writer forces the direction on 2 of 16 samples, which is
  a small asymmetry in the ±1 distribution; and audio carriers, RGBA images with
  transparent pixels and payloads above four million bits fall back to v3. Not
  wired into the GUI — `container_version` is still read from `core.constants`, and
  the interface keeps writing v3 until the layout earns its place.

- The interface names the container layout: the extract tab's audit card shows a
  `FORMAT` row (`v3 · keyed positions` or `v2 · public header · older file`,
  localised), and the embed tab says which layout this build writes. The version
  is authenticated inside the header, so it is reported only after a payload was
  opened; every number comes from `phantom.core.constants`, never a locale file.
- Copied secrets now really leave the system clipboard. Tk's `clipboard_clear`
  only reaches it while Tk owns the selection, and on macOS the text survives the
  window, so the 30 s timer and the window close both call the platform's own tool
  (`pbcopy`, `clip`, `wl-copy`, `xclip`, `xsel`) through an argument vector — never
  a shell — with a 2 s timeout. The clear runs only when the clipboard still holds
  the text PHANTOM put there, so another application's content is never wiped.
- `core.security.secure_zeroize` is the single checked zeroizer behind every key
  wipe: `kdf._zero`, `kdf.wipe_all`, `MessageKeys.wipe()` and therefore both
  envelopes. It zeroes a `bytearray` in place and raises `TypeError` for `str`,
  `bytes` or anything else immutable, so a wipe of a value that cannot be wiped
  fails loudly instead of passing silently. `SECURITY.md` spells out what this

- The audit card's `SIZE` row now reports the share of the carrier the payload
  occupies: `284 B → 306 B · 12 % of the carrier`. It is exact bookkeeping, not a

  bits per ciphertext byte against the carrier's usable bits, and

  `fill_percent` behind the fill bar is left alone, and an unknown carrier prints
  no share at all.
- `tools/bench_steganalysis.py` answers the question the capacity warnings only
  gesture at. Eight generated 512×512 carriers are embedded through the real v3
  engine (LSB matching), written to PNG, read back, and handed to the two classic
  blind detectors — Westfeld–Pfitzmann chi-square and Fridrich's RS. Every carrier
  is measured untouched as well, so a detector that already fires on the cover
  cannot be mistaken for a find, and the run opens with a calibration block on
  synthetic LSB replacement to prove both detectors still work (χ² 0.00 → 1.00,
  RS 0.00 → 0.99 as the replacement rate climbs):

  | load, bpp | PSNR, dB | changed pixels, % | χ² p | RS p̂ | detected |
  |---|---|---|---|---|---|
  | 0.05 | 68.9 | 2.5 | 0.000 | 0.008 | 0/6 |
  | 0.10 | 65.9 | 4.9 | 0.000 | 0.007 | 0/6 |
  | 0.20 | 62.9 | 9.7 | 0.000 | 0.016 | 0/6 |

  LSB matching moves samples by ±1 and keeps the histogram, and the histogram is

- `tools/bench_positions.py` measures what the v3 bootstrap key costs next to the

### Fixed

- **The window can no longer stop on a job that has already finished.** Three
  paths left the footer busy with nothing running: a job that failed between
  setting "busy" and starting its thread kept the flag and no worker ever
  reported back; the poll chain was re-armed only while the *worker* reported
  busy, so a poll that failed in the gap after the last report left the window
  stuck; and the collector pause was recorded per window, so a second window (or
  the next job in a chain) read the collector while the first still held it down
  and concluded "it was never enabled" — the collector then stayed off for the
  rest of the session, which is where the GUI suite found it (`gc.isenabled()`
  False with nothing in flight). The pause is now process-wide and given back as
  soon as the finished job's thread is gone, an abandoned start is rolled back
  before the error is re-raised, and the poll says in the log what it swallowed.

- **Resizing and fullscreen no longer cost a full layout per event.** A drag-resize,
  a zoom and the fullscreen transition deliver a stream of `<Configure>` events — a
  child's configure reaches the toplevel's bind tags, so one step delivers thousands —
  and every event that passed the width filter walked the whole widget tree to find
  the wrapping rows and re-flowed all of them synchronously, inside the event that was
  supposed to be painting. On real Aqua the same four resize steps cost **48.7 ms of
  layout before and 0.4 ms after**; tree walks 29 → 0, `grid_forget` 37 → 0, handler
  time 59.9 ms → 9.5 ms. The first event of a burst now owes one pass on the idle
  queue (Tk's own queue: `update idletasks` is still never called), the rows are the
  list `adopt` already collected, widths are measured once per caption change, a pass
  moves only the children whose cell changed, and a tab nobody is looking at is laid
  out when it is opened (a language switch still lays out all four at once). Same
  breakpoints, same wrapping, same themes, same geometry restore.

- **Drag and drop says it is unavailable when it is.** Tcl/Tk 9 imports
  `tkinterdnd2` and then cannot create its Tcl commands, so every registration failed
  with `invalid command name "tkdnd::drop_target"` while the window kept promising
  drops. The hints now follow `DndProvider.usable` — the module loaded *and* a
  registration succeeded — and the reason is kept for the log. Choosing a file with
  the button never went through that path and still does not.

- **The macOS window no longer crashes when it is built.** The build forced a
  display pass from the constructor, and again for a window that was not on
  screen yet; on Aqua both land in Tk's own idle drawing, which is where Tk's
  open crash reports live (idle tasks that hold a window pointer the window no
  longer owns). The pass is now scheduled for the first idle callback, a hidden
  window's owed pass runs once when it is mapped, and the appearance mode is set
  before the widgets exist, which removes about a hundred nested
  `update_idletasks` calls per dark build. A real-Aqua CI job runs the GUI suite
  on every push so this is checked where it happens, not under Xvfb.

- **Switching the theme no longer segfaults on macOS with Tcl/Tk 9.1.** One click
  notified every registered widget, and each notification ended with its own
  `update_idletasks` — a display pass entered from inside a Tk callback, which on
  Aqua under Tk 9.1 kills the interpreter (exit 139). A theme change now refuses
  every one of those passes and owes exactly one, on the idle callback; on Aqua
  under Tk 9 the window goes further and asks Tk for no display pass at all, for the
  whole run, because CustomTkinter also flushes from its own draws (a scrollbar, a
  colour change) and any of them is the same crash — Tk lays out and paints in its
  own loop a moment later, so nothing the window shows depends on it. Dark, Light
  and System all still switch, the setting is still saved, and on macOS with the
  bundled Tk 8.6 nothing changed: `115 passed, 3 skipped`. The Tk 9.1 CI job drives
  the real window through two full rounds of switching, a resize, a tab switch and
  the close button on Tk's own event loop, and reports the crash it still sees in
  the *pytest harness* (`root.update()` from script level) without letting it decide
  the job — see `docs/macos-aqua-crash.md` §9.

- **Text that has no UTF-8 form is refused, not quietly changed.** A lone
  surrogate (``"\ud800"``) cannot be encoded, and the failure used to surface as a
  `UnicodeEncodeError` from inside the container writer, after the carrier had
  already been read and compressed. `phantom.core.text.require_exact()` now runs at
  every place that turns text into bytes — payload, password KDF, legacy container
  — and raises `InvalidUnicode` (`err.invalid_unicode`, with the code point and its
  position) *before* anything is read, compressed or written: no output, no
  temporary file, the source unchanged. The window checks the same rule while you
  type and shows a warning instead of starting a job, so the password field is
  covered too. Nothing is replaced and nothing is written as WTF-8, because that
  would change the user's text; valid text is byte-identical to before and every
  existing file still extracts.

- **Damaged containers are refused cheaply, while parsing.** A 264 KB PNG whose
  `zTXt` inflates to 256 MiB used to be decompressed in full (before any size
  check); it now stops at `MAX_INFLATE_BYTES` — 17.0 MiB and 0.03 s — and the field
  is shown truncated with a warning instead of killing the process. The XMP limits
  are now applied *during* the parse rather than to a finished tree: a packet with
  70 000 elements costs 6.8 MiB and 0.03 s (it was 11.1 MiB after the tree was
  built), and depth, element and attribute limits are proven with a tripwire on
  `XMLParser.read`. Truncated files, chunk lengths past the end of the file, bad
  CRCs, `.wav` files that are really PNGs and directories are all refusals with a
  code, never a traceback, and a refused clean leaves the source byte-identical
  with no staged sibling behind.

- **Cancel and close leave nothing behind.** Cancelling mid-clean, cancelling the
  same job eight times in a row, closing the window during a job and re-running a
  job after a cancel are all covered: no output file, no staged temporary file, the
  source unchanged, the worker reusable with a fresh cancel event, and
  `shutdown()` waits for the job thread. In the window a cancelled job now puts the
  progress bar back to zero and to determinate mode, restores the stage line, frees
  every action button and recomputes the save button from the plan instead of
  leaving the pre-cancel state on screen.

- **The card says what it means, in the language of the window.** Three residual
  defects in the original report: prose this program writes ("contains personal
  properties", "a property of the packet below") stayed English inside a Russian or
  Ukrainian card — every such sentence now carries a locale key (21 new keys in
  en/ru/uk, values included), while data is never translated and the JSON export
  stays English; the counter printed "unknown 0" beside a visible unknown property
  because the packet's properties are *derived* views — they are tallied by
  `count_derived()` and shown on their own line, with `derived_counts` added to the
  JSON; a disabled save button kept the accent fill, because CustomTkinter only
  greys the caption — `widgets.set_enabled()` swaps in `CLR_DISABLED_FILL` and
  restores the accent when the button comes back; and after a clean the header
  named the source while the numbers described the copy — `report_after` now names
  the file that was written, and the results card opens with which file it
  describes.

- **A protected property inside an XMP packet can no longer be deleted with it.**
  The inspector looked for the text `<dc:rights>` in the packet and treated "I did
  not find a protected property" as "there is nothing to protect". RDF/XML can put
  the same property in a place that search never sees — as an attribute of
  `rdf:Description`, inside a `rdf:Bag`/`Seq`/`Alt`, in a nested node, under a
  prefix the file chooses, or in a namespace PHANTOM does not know — so a file with
  `dc:rights="(c) 2024 …"` on the element and a `photoshop:City` child was offered
  as "personal data only" and the whole packet was removed, copyright line
  included, while the result claimed `verified: True`.

  `phantom.metadata.xmp` now reads the packet structurally and decides in the
  other direction: a property is removed only when the reader has *proved* it is
  personal and the packet holds nothing else. Everything unrecognised — rights,
  descriptive, provenance, unknown namespaces, unknown local names, and every
  shape the reader does not model — blocks the whole packet, because XMP is
  removed as a packet and there is no partial removal. A packet that cannot be
  read completely is protected as well: truncated XML, a DTD or an entity
  declaration (refused before parsing, so no entity is ever expanded and nothing
  is fetched), more elements, attributes or nesting than the limits allow, a
  packet over 1 MiB or packets over 4 MiB together. Several packets in one file
  are read together, one unreadable packet protects the others, and a rewrite that
  would drop a packet the plan promised to keep still fails the integrity
  confirmation and publishes nothing.

  The properties of the packet are listed one by one, including the ones in a
  namespace this build does not know, so refusing to remove is never the same as
  refusing to look. The reason a packet is kept is a locale key: it is shown in
  the language of the window instead of English inside a Ukrainian card, and the
  plan card says that personal data sits in a block that may not be removed
  instead of «очистка не требуется». The save button follows the plan it would
  execute — a selection that would remove nothing no longer enables it.

- **The scroll wheel and the trackpad, properly this time.** The previous attempt
  bound a handler on every widget of a tab and was wrong in three ways that only
  show up on a real machine:

  * **The event was bound on the wrong thing.** Aqua delivers a wheel event to the
    *window under the pointer*, with `event.widget` being that window — so a
    per-widget handler either never ran or scrolled the wrong tab. Routing is now
    one application-level `bind_all` (the one place a global binding is the right
    tool, and CustomTkinter's own is removed first so nothing scrolls twice),
    which resolves the target at event time with `winfo containing` and walks up
    from whatever is actually under the pointer. A tab that is not on screen, a
    scrollbar and a text box all resolve to nothing; a text box keeps its own
    wheel because its class binding has already run.
  * **`<TouchpadScroll>` was bound but never decoded.** On Tk 9 a precise device no
    longer produces `<MouseWheel>` on macOS *or* Windows: the two pixel deltas
    arrive packed into `%D`, X in the high 16 bits and Y in the low 16, and must
    go through `tk::PreciseScrollDeltas`. Read as a wheel notch the packed value is
    up to 4 294 967 336 units, i.e. a jump to the end of the document. The two
    event kinds are now handled separately — pixels for the touchpad
    (`yview moveto` on the fraction of the *scroll region*, the same formula Tk's
    own `ScrollByPixels` uses, clamped at 400 px per event so a momentum fling is
    not one jump), notches for the wheel — and the decode prefers Tk's own proc,
    with a bit-exact Python fallback for a Tk whose library lacks it.
  * **One delta-per-notch for every platform.** Aqua Tk 8.6 reports the raw Cocoa
    delta (about ±1 per notch), Aqua Tk 9 and Windows report ±120, and the old
    fixed multiplier turned nine notches into 27 units on one and 9 on the other.
    `scroll.WheelGeometry` derives the scale from `info patchlevel` *and*
    `tk windowing system`: 3 units per notch on macOS, 20 on Windows, 1 on X11,
    with a per-area accumulator so a sub-notch delta is banked instead of rounded
    to nothing.

  `PHANTOM_SCROLL_DEBUG=1` (or a path) turns on an event trace — event type and
  serial, Tk patchlevel, windowing system, raw `%D`, the decoded deltas, the widget
  under the pointer, the chosen area and the `yview` before and after — which is
  what any remaining report about scrolling should be diagnosed with. The startup
  log line names the Tk version, the backend and the maths in use.

  Covered by `tests/test_scroll.py` without a display (decode parity with Tk's
  proc, geometry per platform and Tk version, the routing precedence, the
  accumulator, the trace) and in `tests/test_gui.py` through the real event loop:
  a wheel event generated on the root window scrolls the tab under the pointer and
  not its neighbours, a text box is left alone, and — on Tk 9 — a packed
  `<TouchpadScroll>` moves the canvas by pixels instead of jumping.
- **A failed embed no longer destroys the file that was already at the output
  path.** The self-check ("read the file back and compare") ran *after* the
  writer had replaced the destination, and a failure then deleted the output
  path outright — so a verification problem, a cancellation or a short write cost
  the user the only copy of whatever used to live there. The output now goes to a
  hidden sibling (`files.staged_path`), verification runs on that file, and
  `files.publish_staged` renames it into place only after the check passes; on
  any failure the staged file is removed (`files.discard_staged`, a `WipeError`
  if even that fails) and the destination is untouched, byte for byte. The forced
  extension still wins — asking for `a.jpg` still publishes `a.png` — and the
  "output would overwrite the carrier" check moved into the API, because the
  writers now only ever see a temp name.
- **The wheel works on a macOS trackpad.** Two things were wrong and neither was
  the binding: a trackpad reports *fractional* deltas (±0.1 per event), and
  `int(delta)` turned every one of them into zero; and Tk 9 reports two-finger
  scrolling as its own `<TouchpadScroll>` sequence, which nothing bound. The new
  `scroll.WheelAccumulator` carries the fraction between events of the same tab
  (ten tenths of a notch move one line, three nines of a unit stay banked), each
  scrollable area gets its own accumulator so two tabs cannot borrow each other's
  remainder, and `<TouchpadScroll>` is bound alongside the classic three
  sequences — Tk 8.6 refuses it per widget and the rest still binds. `MouseWheelRouter`
  became `scroll.install_tab_wheel`, one handle per tab with `refresh`/`uninstall`,
  still no `bind_all`.
- **The writer can no longer produce a container it cannot open.** Compression was
  bounded only by what fitted into the carrier, never by the plaintext limit the
  extractor enforces (`C.MAX_PLAINTEXT_BYTES`, 1 GiB); a payload above it embedded
  fine and then failed to unpack — the same build refusing its own file. The
  ceiling is now checked while streaming in `payload._compress_stream`, and both
  ends read the same constant.
- **A job that finished between two polls no longer loses its result.** `_poll`
  drained the queue, saw `worker.busy == False` and finished the operation without
  looking again, so a thread that died in that window left its DONE (or ERROR,
  or CANCELLED) in the queue forever: the embed succeeded, and the interface never
  showed the output path or the verification verdict. The worker guarantees the
  ordering — it posts the terminal event before the thread stops — so `_poll` now
  drains a second time once `busy` goes false, and re-checks afterwards in case
  handling those events started the next job.

### Changed

- **The 2026 look: readable secondary text and larger type.** `CLR_MUTED` was one
  mid-grey for both appearance modes (~4.8:1 on a white card, ~3.4:1 on the dark
  one) and painted the card headings, so on the dark theme they faded into the
  card; it is now `#4B5563` light / `#9CA3AF` dark, 7.6:1 and 6.8:1. The type
  scale lives in `theme.FONT_SIZE_*` instead of a literal at every call site: body
  text and card headings at 14, hints at 13, mono values at 13, the footer at 11.
- **The embed tab names the layout the carrier will really get.** It always said
  v5, but audio carriers fall back to the keyed layout — WAV/FLAC now read
  `v3 · keyed positions`, images keep v5, and the badge repaints when a carrier is
  probed. (A transparent PNG falls back the same way; only the writer can be
  certain, so that case still shows the default.)


- **v5 (syndrome trellis) is now the layout this build writes.** Embedding from
  the interface, the API or the engine with no `container_version` produces a v5
  file; the embed tab says so before the user presses Save
  (`v5 · синдромный решётчатый код`) and the audit card names the layout of an
  opened file. `C.CONTAINER_VERSION` moved to 5 and a new
  `C.KEYED_CONTAINER_VERSION` (3) names the older keyed layout, which is now the
  *fallback*: audio carriers, images with transparent pixels and payloads no block
  layout fits still fall back to it, and the header then says v3. v2, v3 and v4
  files remain readable — the suite writes one of each and extracts it next to a
  v5 file.

  Making it the default needed the cost map to stop being the bottleneck. The
  embedder now builds costs with `adaptive.embedding_costs`: single precision,
  reusable buffers, no full-plane temporaries, and **one wavelet scale** instead
  of two. A single scale turned out to be not just 2× cheaper but slightly
  better — on the eight benchmark covers at 0.2/0.4 bpp it selects changes with
  PSNR 66.89/63.04 dB and 4.02/9.71 % of pixels touched, against 66.77/62.76 dB and
  4.17/10.48 % for the two-scale map, because the coarse scale mostly steered
  changes into mid-frequency texture where they buy nothing. (The half-resolution
  step described further down takes the same map down by another factor of four.)
  `cost_map` — the float64 map the v4 layout reproduces from the stego image — is
  untouched, so existing v4 files still open.

  Two structural fixes came out of the same work. The trellis body is now walked a
  chunk of blocks at a time (`stc.sliced`, `STC_CHUNK_SLOTS`): a 24 MP carrier has
  72 M usable slots, and materialising the keyed order for all of them cost 576 MB
  of int64 indices plus another 288 MB for the costs — enough to get the process
  OOM-killed at 4 GB. And the Feistel round now assembles its AES input in one
  buffer instead of a zeros/astype/view/tobytes chain, which is bit-identical
  output (checked against the previous implementation on 5 000 and 3 000 000
  indices) for a third less time.

  Measured on a 24 MP carrier with a 100 KiB payload through the public API,
  extraction round-tripped and verified:

  | | before v5 became the default | now |
  |---|---|---|
  | embed (API, includes the read-back check) | did not finish (OOM at 4 GB) | 27.5 s |
  | extract (API) | — | 10.2 s |
  | peak RSS | — | 728 MB |
  | cost map alone | 43.9 s / 2.1 GB | 2.1 s / ~0.7 GB |

- **The trellis cost map is computed at half resolution.** A cost map is a smooth
  field — it says "this region is busy", not "this pixel is" — so `embedding_costs`
  now averages every channel 2×2 down, runs the wavelet chain on the quarter-size
  plane and repeats each cost back over its 2×2 block. Together with the single
  detail scale that is 16× less arithmetic than the original two-scale float64 map:
  on a 24 MP photo the map itself takes **2.1 s** instead of 43.9 s, and the whole
  API embed drops from 61 s to **27.5 s** with a peak of 728 MB instead of 984 MB.

  It costs a quarter of a decibel and nothing else that the benchmark can see: on
  the eight covers at 0.2/0.4 bpp the full-resolution map selects changes with PSNR
  66.89/63.04 dB and 4.03/9.69 % of pixels touched, the half-resolution one
  66.64/62.86 dB and 4.36/10.18 % (a two-scale map at the same resolution is
  slightly worse and twice as expensive: 66.59/62.76 dB). Across the full
  three-layout benchmark the v5 columns barely move — PSNR within 0.02 dB of the
  previous run at every load, `Σρ/bit` unchanged at 0.17–0.22 — while the run itself
  drops from 229.1 s to 142.7 s. The ranking agrees with the slow map, too:
  correlation 0.977, and the cheapest fifth of the fast map sits at the 20th
  percentile of the full-resolution one. There is no size threshold; carriers under
  `COST_MIN_SIZE` (8 px) keep the exact map because a 2×2 average would leave the
  wavelet nothing to look at.

- `tools/bench_steganalysis.py` and `tools/bench_positions.py` name the layouts
  explicitly (`v3` is the keyed layout, not "the current one"), the steganalysis
  header lists all three with the default marked, and the positions benchmark
  gained a v5 row.

### Security

- Container format v3: the positions of **every** bit in the carrier, the sealed
  header included, are derived from the password, so nothing sits at a place a
  reader without the password can compute. Previously the header was placed by
  a constant-seeded permutation, which told an attacker exactly which 400 bits
  to read before knowing anything. The position key is PBKDF2-HMAC-SHA256
  (600000 iterations) over the password with a fixed domain salt — the
  per-message salt lives inside the header, which cannot be found before the key
  exists — and is HKDF-separated from the message keys, so the choice of KDF
  profile for the payload does not move a single bit. Trade-off documented in
  `SECURITY.md`: for one password and one carrier size the layout is the same in
  every file.
- Version 2 carriers still open: extraction tries the v3 layout, then the v2
  one, and the version is authenticated inside the header, so one layout can
  never pass as the other. `stego.engine.embed_payload(container_version=…)`
  writes the v2 layout for files an older build has to open; the app itself
  always writes v3.
- New tests pin the property that mattered: two passwords place the header in
  different slots, the header never overlaps the payload, a v3 carrier does not
  authenticate through the v2 positions, and a golden v2 fixture written before
  this change keeps extracting (text, file name and SHA-256 unchanged).
- Refuse an output path that resolves to the file being hidden, including the
  path the forced output extension produces and paths reached through symlinks;
  the check now runs before anything is written, with or without secure deletion.
- Sanitise every file name read from a container: one path segment, no
  separators, no control or Windows-reserved characters, `""`, `.` and `..`
  rejected, the joined path re-checked against the resolved output directory.
- `EmbedOutcome.verified` now reports a self-check that actually ran, a source
  file is never wiped without it, and the UI says "not verified" instead of
  "saved" when verification is off.
- Restored files are written to a temp file, read back, compared with the sealed
  SHA-256 and only then replaced, so a failed or attacked write keeps an existing
  file intact; they are created `0600` on POSIX.
- Corrected the threat-model text: the header positions are known, decryption
  without the password is impossible, but the presence of steganography is
  detectable by statistical analysis. PBKDF2 is documented as an explicitly
  selected profile, never an automatic downgrade.

## [2.1.0] — metadata inspector and privacy cleaner

The steganography path is untouched: same formats, same cryptography, same
readers. 2.1.0 adds a fourth tab that answers a different question — what does
this file carry besides the picture or the sound, and what happens if we take it
out? The release also contains the scroll-router and progress work listed under
`[Unreleased]` above.

### Added

- **`phantom.metadata`, a new package:**
  `models` (fields, categories, counts, provenance states), `png`, `wav` and
  `flac` (chunk and block walkers with serialisers), `inspector` (content
  detection, hashing, reports), `cleaner` (planning, rewriting, publishing),
  `integrity` (decoded fingerprints and comparison), `provenance` (C2PA/JUMBF
  detection) and `report` (TXT and JSON exports). No new third-party dependency:
  Pillow, Mutagen, NumPy, SoundFile and the standard library only.
- **Content-based format detection.** PNG, WAV and FLAC are identified from their
  signature bytes, never from the file extension; anything else is refused with
  `ErrorCode.UNSUPPORTED_FORMAT` instead of being parsed by the wrong reader.
- **A read-only inspector with six categories.** PNG (chunks, tEXt/zTXt/iTXt,
  TIFF/EXIF including GPS, XMP, ICC, tIME, unknown chunks, per-chunk CRC), WAV
  (RIFF, `fmt `, `data`, LIST/INFO, `bext` v0–v2 with reserved bytes and coding
  history, iXML, ID3, unknown chunks) and FLAC (STREAMINFO, Vorbis comments,
  PICTURE, APPLICATION, SEEKTABLE, CUESHEET, PADDING, unknown blocks) are reduced
  to fields that carry a name, a value, a container, a category (personal,
  descriptive, technical, rights/attribution, provenance, unknown) and an
  editability marker.
- **Selective cleaning with a plan shown first.** Personal fields are preselected;
  attribution fields (EXIF `Artist`, PNG `Author`, RIFF `IART`, Vorbis `ARTIST`)
  are offered unticked; copyright, licence, technical fields, colour profiles,
  provenance blocks and unknown chunks are protected and never removed
  automatically. The plan reports what will be removed, what will be kept and what
  was requested but is protected.
- **Mandatory post-clean verification.** Pixels, alpha and chunk CRCs for PNG;
  every PCM sample, bit depth, sample rate, channel count, frame count and
  duration plus a full re-decode for WAV/FLAC; the metadata is re-read to prove the
  selected fields are gone, the protected ones are intact and the field count
  matches the plan. Whole-file SHA-256 and decoded-content SHA-256 are reported
  separately, and the interface explains why only the second one must not change.
- **C2PA / content-credential detection, without pretending to validate it.** A
  manifest or a signature block is reported as "manifest found, signature not
  verified" (the trust list and certificate chain are not part of this build), and
  a signed file is refused by the cleaner instead of being rewritten into a file
  that still claims a signature it no longer satisfies.
- **The fourth tab** (`СКРЫТЬ` · `ИЗВЛЕЧЬ` · `МЕТАДАННЫЕ` · `НАСТРОЙКИ`) with five
  cards: file selection (button and drag & drop), analysis results (counts,
  category filter, removable-only filter, field rows with checkboxes, warnings),
  cleaning settings (select all editable, select personal, clear, pre-report),
  saving (path, save cleaned copy, export TXT/JSON, copy report, reveal in the file
  manager) and the integrity card (decode status, content comparison, both hashes,
  removed/kept counts, verdict).
- 85 new locale keys in all three languages (302 total, parity enforced by
  `tests/test_i18n.py`), including `err.signed_media`, `err.metadata`,
  `stage.scanning` and `stage.cleaning`.
- `ErrorCode.SIGNED_MEDIA`, `ErrorCode.METADATA`, `Stage.SCANNING` and
  `Stage.CLEANING`.
- Tests: `tests/test_metadata_inspect.py`, `tests/test_metadata_clean.py`,
  `tests/test_metadata_report.py`, `tests/test_metadata_view.py` and a
  `metadata_samples` builder that generates PNG/WAV/FLAC files with known
  metadata (no new binary fixtures), plus GUI coverage of the new tab in
  `tests/test_gui.py`.

### Changed

- The window has four tabs, so the scroll router registers one area per tab,
  `metadata` included, and still exactly one global wheel handler. The metadata
  field rows live in the tab that carries them: a `CTkScrollableFrame` inside
  another one makes the two canvases chase each other's `<Configure>` events,
  which is a layout storm and a scroll bug waiting to happen on the platform the
  router was written for.
- `Cmd/Ctrl+1…4` now select `embed`, `extract`, `metadata` and `settings`
  (`Ctrl+3` was `settings` before); the previous tab is still restored on launch.
- `AppSettings.normalized()` accepts `"metadata"` as a saved last tab.

### Fixed

- **Undo and redo keep working from the action bar.** Tk reports every change with
  the same `<<Modified>>` event and says nothing about who caused it, so the event
  an undo queues for itself arrived after the handler had re-armed "redo available"
  and cleared that flag again: the redo button stayed grey until the next keystroke.
  The edits the window performs itself are now counted and their events are
  recognised as its own — a keystroke never bumps that counter, so it is always
  treated as a keystroke (pinned by a GUI test that cuts, undoes and redoes).
- **A long job can no longer freeze the window on a slow machine.** A worker
  thread allocates, so it can start a cyclic garbage collection, and a collection
  runs finalizers — `tkinter.font.Font.__del__` calls into Tcl, which is not
  thread-safe. When the finalizer landed on the worker, Tk waited for a main loop
  that was waiting for the job, and the operation never finished. The collector is
  now paused for the length of a job and every finalizer runs on the thread that
  owns Tk (`_pause_collection_for_job`/`_resume_collection_after_job`, pinned by a
  GUI test).
- **One handler that raises no longer wedges the interface.** Worker events are
  dispatched from an `after()` callback; the traceback used to take the callback
  with it, so the chain was never re-armed and the window stayed "busy" for an
  operation that had already ended. The event loop now logs the traceback, finishes
  the operation and paints an error instead.
- **Cleaning an EXIF/GPS dossier no longer fails with a tag number.** Reported from
  a real macOS run: a PNG with a position, two dates, make, model, owner and body
  serial numbers ended with `Ошибка обработки метаданных: png.gps.0x0000` and no
  cleaned copy. The pre-report offered the derived *GPS coordinates* row as one
  removable field and translated it into every GPS tag, `GPSVersionID` included;
  the last check before publishing then refused, correctly, to write a file that had
  lost a field the plan promised to keep. Three things were wrong and are fixed:
  * the position is now a **derived view** — shown, but not an entry: it is not
    selectable, it is not counted (so one position no longer looks like six
    personal fields) and removing the four tags behind it removes it, which is no
    longer read as "a protected field disappeared";
  * `removal_from_keys` maps one key to one tag and nothing else: no selection can
    widen into tags the user did not tick;
  * every field the plan offers is now a field the rewrite can actually do — a
    property test removes each removable key of the files in the suite, one at a
    time, and asserts that nothing protected was lost.
- **Structured blocks that are removed as a whole are no longer offered when they
  carry something protected.** An XMP packet with a title or a rights line in it is
  reported as protected, with the reason, instead of being offered and then failing
  (the packet also deleted `dc:rights` along with the city). Its properties are
  derived views, so they are not counted twice either. `png.xmp` — the only key a
  user can tick — was never mapped by the rewriter at all (the parser required three
  dot-separated parts), so removing an XMP packet did nothing; it now works.
- **A failed or cancelled operation empties the progress bar.** It used to keep the
  fraction the job had reached, which reads as "still running" when nothing is.
- **The policy guard has its own error and its own sentence.** `ErrorCode.METADATA_CONFLICT`
  / `MetadataConflictError` (uk/ru/en) names the field by label instead of by tag
  number, says the source was not modified and that no cleaned copy was created, and
  states that it is a bug in the cleaning policy rather than something the user did.
  The guard itself is unchanged: nothing is published when it fires.
- Tests: `tests/test_metadata_exif_gps.py` (18 tests) builds the dossier that failed
  — `GPSVersionID`, both coordinate pairs and their references, both dates, make,
  model, owner, body serial, orientation, software, artist, copyright and one tag no
  table knows — and checks detection, the preselection, the plan against the written
  result, the survival of every protected tag, pixel identity, chunk CRCs, the
  untouched source, that a failing guard publishes nothing, partial GPS selections,
  unknown tags, cleaning twice, and the same property for WAV and FLAC.

### Security

- The cleaner refuses a file whose path resolves to the source, refuses to
  overwrite an existing file without explicit permission, and publishes only
  through a staged sibling that is renamed into place after verification.
- Metadata is never executed, never interpolated into a shell command and never
  written to diagnostic logs; the exports contain the personal values and are
  therefore produced only on an explicit user action.
- The documentation and the reports state plainly that removing metadata is not
  anonymisation and that a missing manifest is not proof that a file carries no
  traces.

## [2.0.0] — release candidate

Released under the MIT license (see `LICENSE`).

Complete rewrite of the 1.x single-file application. Existing v1 files remain
readable; new files are written in the v2 format.

### Added

- Versioned, authenticated container: 50-byte sealed header, AES-256-GCM with
  fresh salt and nonce, AAD binding the header, version and KDF profile.
- Argon2id key derivation (m=96 MiB, t=3, p=1) as the default profile, with
  PBKDF2-HMAC-SHA256 (600000 iterations) selectable.
- Feistel permutation spreading the payload across the whole bit plane instead
  of sequential LSB, seeded from the public header.
- PNG carriers: 1/2/4/8-bit, colour types 0/2/3/4/6, transparency-aware capacity,
  palette and bitmap notices, lossless expansion of 1/2/4-bit images,
  deliberate refusal of 16-bit and APNG.
- Audio carriers: WAV 8/16/24/32-bit and FLAC 16/24-bit, with a hand-written
  RIFF parser that preserves chunk layout, odd-size padding and metadata;
  lossy formats refused before reading.
- Payload metadata `type | name | sha256 | length | zlib`, filename sanitising
  and forced output extensions.
- Self-check before publishing: the output is re-read and the payload extracted
  and compared with SHA-256; failure leaves no file behind.
- Shredding with progress, `fsync` per chunk, and an explicit warning that
  overwriting is risk reduction rather than a guarantee.
- CustomTkinter interface: three languages with key and placeholder parity,
  Dark/Light/System themes, drag & drop, debounced capacity estimation, animated
  progress, clipboard auto-clear after 30 seconds.
- Worker thread with progress queue, cooperative cancellation and a watchdog;
  no Tk call is made from any thread but the main one.
- Test suite: stub scanner, known-answer vectors for Argon2id/PBKDF2/AES-GCM,
  legacy golden fixtures generated from the original commit, WAV/FLAC round
  trips verified by a second decoder, property tests, GUI smoke tests under
  Xvfb. The GUI tests never open a real modal dialog — dialogs are recorded and
  fail the test with their text, so a stuck message box cannot hang CI.

### Changed

- Layout split into `phantom.core`, `phantom.stego`, `phantom.audio`,
  `phantom.ui`, `phantom.i18n`; `core.py` removed.
- Capacity formula now subtracts the 16-byte GCM tag, so an exactly-sized
  payload no longer overflows the permuted range.
- Locale strings no longer hard-code KDF numbers; they are formatted from
  constants at run time.
- Locales grew to 205 keys (paste/copy buttons, context-menu items, result
  window) with full uk/ru/en parity.

### Fixed

- macOS text editing: `Cmd+C/V/X/A` works in every entry and textbox, a
  right-click menu offers Paste/Copy/Cut/Select all, and `PASTE` / `COPY KEY`
  buttons next to the password fields cover systems where the shortcut never
  arrives. The shortcuts are bound on the inner Tk widget, so they cannot be
  swallowed by CustomTkinter proxies and cannot paste twice.
- Scrolling: the mouse wheel and the trackpad scroll the whole tab instead of
  only the scrollbar. Wheel events are routed from any child widget to its
  scrollable frame, the macOS delta is inverted instead of being divided by 120
  (which rounded a trackpad notch to zero), and a text box keeps the wheel while
  it still has room to scroll itself.
- Reading results: `EXPAND` opens the result at 80 % of the screen with a
  read-only, selectable copy of the text plus `COPY TEXT`, `COPY PATH`,
  `SHOW IN FINDER` (`open -R` / `explorer /select,` / `xdg-open`) and `CLOSE`;
  the main result row gained the same path actions.

- AES-256-GCM is now used correctly (1.x reused salt and nonce in places).
- The GUI smoke tests drive the real widgets: the embed test used to fill only
  the view model, so the app rejected the request and blocked on a modal error
  box. CI also caps the GUI step and echoes its log as annotations.
- Lossy audio is now refused by file signature before the extension is trusted,
  so a `.wav`-named OGG/MP3 (including an `ID3`-prefixed file) cannot slip
  through and be read as PCM.
- A missing `libsndfile`/`soundfile` reports `AudioFormatError` instead of
  escaping as a bare `ImportError` from the FLAC reader.
- LSB matching no longer skips pixels whose channel is 0 or 255.
- v1 extraction no longer reports a spurious integrity failure when the payload
  was written by the original application.

### Removed

- Unreachable validation branches that duplicated a check already enforced by
  the caller (`Payload` filename length, capacity after compression, WAV splice
  length, the password-class guard in `generate_password`), and an unreachable
  FLAC sample-range guard.

- The monolithic `core.py` and the duplicated logic it carried.
- Any wording in the interface that implied undetectability.
