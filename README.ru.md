# PHANTOM 2.1.0

Скрывает зашифрованные данные внутри PNG-изображения или аудиофайла WAV/FLAC и
извлекает их на другой машине по тому же паролю. Полезная нагрузка шифруется до
того, как в носитель записывается первый бит, и приложение не обещает больше,
чем реально делает код.

- Шифрование: **AES-256-GCM**, новая соль и nonce для каждой операции
- Ключ: **Argon2id · m=96 MiB · t=3 · p=1** (PBKDF2-HMAC-SHA256 с 600000
  итераций — отдельный профиль, который выбирают явно при встраивании; он не
  подставляется автоматически, если Argon2id недоступен: это была бы тихая
  деградация)
- Контейнер: версионированный, аутентифицированный, без magic-строки в открытом виде
- Интерфейс: CustomTkinter, три языка (Українська / Русский / English),
  темы Dark / Light / System, drag & drop, четыре вкладки
  (`СКРЫТЬ` · `ИЗВЛЕЧЬ` · `МЕТАДАННЫЕ` · `НАСТРОЙКИ`)
- Инспектор метаданных и очистка приватности для PNG, WAV и FLAC: что несёт файл,
  что можно удалить и проверенная очищенная копия
- Без сетевых вызовов, телеметрии и облака

`phantom.__version__ == "2.1.0"`, стадия: release candidate.

## Что это и чем это не является

Это **файловый контейнер в стеганографической оболочке**. Оболочка переживает
копирование, переименование и пересохранение файла без потерь. Она **не
переживает** ничего, что перекодирует медиа: экспорт в JPEG, режим «фото» в
мессенджере, транскодирование звука, изменение размера, обрезку или скриншот.
В мессенджерах отправляйте файл **как документ**.

LSB-стеганографию выявляют статистические детекторы. Приложение никогда не
утверждает, что нагрузку невозможно найти, — это было бы неправдой. Зато формат
не оставляет данных на известном месте: начиная с v3 позиции всех битов носителя,
включая зашифрованный заголовок, выводятся из пароля, поэтому без пароля читать
нечего, а неверный пароль неотличим от носителя без данных. Файлы, записанные в
раскладке v2 (заголовок на постоянных позициях), по-прежнему читаются. Сам факт
стеганографии — отдельный вопрос, и статистический анализ на него отвечает.

Начиная с **v5** эта сборка по умолчанию пишет нагрузку свёрточным кодом с
решёткой (syndrome-trellis). Карта стоимости на вейвлете Добеши показывает, где
изображение «занято», а решётка ищет самую дешёвую *комбинацию* правок ±1, которая
несёт нагрузку, вместо равномерного разброса битов. На ту же нагрузку уходит
примерно вдвое меньше изменений, искажение меньше в 2–3 раза, PSNR выше на 3–4 дБ,
а оценка RS, которую поднимала жадная раскладка (v4) до 0.098, возвращается на
уровень v3 (трёхсторонняя таблица — в CHANGELOG). Карта стоимости считается по
копии каждого канала в половинном разрешении — карта описывает области, а не
пиксели, — поэтому выбор остаётся тем же при вчетверо меньшем объёме вычислений, а
цена — 0.25 дБ (66.64 против 66.89 дБ при 0.2 bpp; это именно компромисс, и в
`SECURITY.md` он так и назван). Долгие операции говорят, что делают: подвал окна
называет фазу, крутит индикатор, пока считается карта стоимости, и отсчитывает
секунды — 24-мегапиксельное фото, которое обрабатывается полминуты, больше не
выглядит как зависшая программа.

Всё старое по-прежнему открывается, и карточка аудита называет раскладку файла:
**v2** (старый открытый заголовок), **v3** (ключевые позиции), **v4** (жадная
адаптивная, включается через `container_version=4`) или **v5** (решётка, по
умолчанию). Если носитель решётку не тянет — звук, изображение с прозрачными
пикселями, нагрузка, для которой не находится блочная раскладка, — запись
откатывается на v3, и заголовок честно говорит v3.

Модель угроз полностью описана в [`SECURITY.md`](SECURITY.md) (по-английски) и
в блоке «Что НЕ защищает» внутри приложения (на вашем языке).

## Требования

- Python 3.10+ (разработка на 3.11)
- Tk 8.6 для графического интерфейса (входит в сборки python.org для Windows и
  macOS; в Linux установите `python3-tk`)

## Установка

```bash
python -m venv .venv
. .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск

```bash
python app.py                   # из корня репозитория
python -m phantom               # после `pip install -e .`
```

Лаунчер добавляет `src/` в `sys.path`; для запуска из репозитория установка не нужна.

## Использование

1. Выберите носитель. PNG (1/2/4/8-бит, без анимации) для изображений; WAV
   (8/16/24/32-бит) или FLAC (16/24-бит) для звука. Форматы с потерями — MP3,
   AAC, M4A, OGG, OPUS, WMA — отклоняются сразу: транскодирование уничтожает данные.
2. Посмотрите строку ёмкости. Она равна `(usable_bits - 400) / 8 - 16` байт:
   400 бит на закрытый заголовок, 16 байт резервируются под тег GCM. «Полезные
   биты» — это один бит на цветовой канал каждого полностью непрозрачного
   пикселя либо один бит на канал каждого сэмпла звука.
3. Введите секрет или выберите файл. Текст сжимается, файл сохраняет имя; и то и
   другое хешируется SHA-256 и аутентифицируется.
4. Введите пароль не короче 12 символов. Похожие внешне Unicode-пароли
   нормализуются по NFKC, поэтому пароль, набранный в другой раскладке, всё равно
   откроет файл. Можно сгенерировать пароль из 20 символов.
5. Сохраните. Приложение пишет во временный файл, перечитывает его, извлекает
   данные обратно и сравнивает SHA-256 **до** того, как готовая копия заменит
   целевой файл. Если проверка не прошла, ничего не публикуется.
6. Для извлечения откройте носитель, введите пароль и сохраните текст или файл.
   В карточке аудита появится раскладка, с которой записан файл: v5 (решётка —
   то, что пишет эта сборка), v4 (адаптивная), v3 (позиции выводятся из пароля)
   или v2 (старый открытый заголовок), рядом с шифром, KDF-профилем, проверкой
   целостности и размерами.
   В строке размера видно и долю носителя, занятую нагрузкой, — по битам, которые
   контейнер действительно записал: `284 B → 306 B · 12 % носителя`. Вкладка
   встраивания заранее показывает, какую раскладку пишет эта сборка.
   Имена выходных файлов очищаются, расширение принудительно выставляется.

### Редактирование, прокрутка и чтение результата

Текстовые поля ведут себя как нативные на всех платформах:

- `Cmd+C/V/X/A` и `Cmd+Z` / `Cmd+Shift+Z` на macOS, `Ctrl+C/V/X/A`,
  `Ctrl+Z` / `Ctrl+Y` / `Ctrl+Shift+Z` в остальных системах, плюс меню по
  правому клику (двумя пальцами) со пунктами «Отменить», «Повторить»,
  «Вырезать», «Копировать», «Вставить», «Выделить всё» и — в поле полезной
  нагрузки — «Очистить поле». Каждое сочетание вешается на внутренний
  Tk-виджет, поэтому прокси CustomTkinter его не проглатывает, а каждая команда
  — один обработчик для клавиши, меню и виртуального события Tk, так что дважды
  ничего не выполняется.
- **Панель действий под полем полезной нагрузки**: вставить, копировать,
  вырезать, выделить всё, отменить, повторить, копировать всё и очистить поле.
  Каждая кнопка вызывает тот же обработчик, что сочетание клавиш и пункт
  контекстного меню, поэтому кнопка и `Cmd+C` не могут разойтись, а доступность
  следует за полем: «копировать» нужен выделенный фрагмент, «копировать всё» —
  текст, а во время операции и в режиме файла доступно только чтение.
- Поле полезной нагрузки принимает текст любого размера ещё до выбора носителя,
  сохраняет его при смене носителя и никогда не режет, не обрезает и не теряет.
  Одна строка длиннее `EDITOR_WRAP_LINE_LIMIT` (20 000 символов) выключает перенос
  слов — это решение только о показе, о нём сказано под счётчиками, — потому что
  перенос в Tk стоит секунды на каждые 100 000 символов одной строки и ничего не
  стоит на тексте с переводами строк.
- `ОЧИСТИТЬ ПОЛЕ` рядом со счётчиками очищает поле и только поле: пароль,
  носитель, путь вывода и настройки остаются. `Cmd+Z` возвращает текст.
- Карточка ёмкости отвечает на вопрос «сколько влезет» числами самого движка:
  носитель (имя, формат, размер на диске, разрешение или длительность),
  нагрузка (символы, байты UTF-8, подготовленный размер), ёмкость (доступно,
  занято, свободно, процент, избыток) — в одной шкале, с явными состояниями:
  нет носителя, нет текста, идёт расчёт, помещается, не помещается, ошибка
  расчёта. Оценка предварительная по построению — окончательной остаётся
  проверка ёмкости внутри движка при встраивании, — и пока числа неизвестны или
  не помещаются, встраивание запрещено.
- Кнопки `ВСТАВИТЬ` и `КОПИРОВАТЬ КЛЮЧ` рядом с обоими полями пароля — на случай,
  когда системное сочетание до приложения не доходит.
- Колесо мыши и трекпад прокручивают всю вкладку, а не только ползунок, и
  прокручивают ту вкладку, **над которой стоит указатель**. Один маршрутизатор на
  всё приложение определяет цель по положению указателя в момент события
  (`winfo containing`), поэтому вешать обработчик на каждый виджет больше не
  нужно, а вкладку, которой не видно, прокрутить нельзя. Два вида событий
  обрабатываются по-разному: `<TouchpadScroll>` (Tk 9, macOS и Windows) несёт две
  пиксельные дельты, упакованные в `%D`, и раскодируется через
  `tk::PreciseScrollDeltas`, а `<MouseWheel>` — это число «щелчков», масштаб
  которого берётся у работающего Tk (Aqua 8.6 даёт ±1 за щелчок, Aqua 9 и
  Windows ±120, X11 — одну единицу).

  Текстовое поле оставляет колесо себе только пока может двигаться в ту сторону,
  куда просят: пустое поле, поле, содержимое которого видно целиком, или поле на
  последней строке передают то же событие странице под собой — поэтому прокрутка
  больше не «застревает» над текстовым полем. Один жест обрабатывается один раз:
  маршрутизатор повешен и на сами текстовые поля, и глобально, а уже обработанное
  событие игнорируется. Указатель над ползунком, списком, шкалой или скрытой
  вкладкой не трогается. Переменная `PHANTOM_SCROLL_DEBUG=1` (или путь к файлу)
  включает журнал каждого события прокрутки: тип, версия Tk, оконная система,
  сырые и раскодированные дельты, виджет под указателем, выбранная область и
  `yview` до и после.
- Буфер обмена считается открытым: скопированный пароль, ключ или результат
  очищаются через 30 с и ещё раз при закрытии окна — штатным средством системы
  (`pbcopy`, `clip`, `wl-copy`, `xclip`, `xsel`), а не только через Tk: Tk
  добирается до системного буфера лишь пока сам им владеет. Если за это время
  содержимое подменило другое приложение, оно не трогается.
- **Карточка результата копирует и сохраняет всю нагрузку, а не предпросмотр.**
  Рядом с результатом: `ВЫДЕЛИТЬ ВСЁ`, `КОПИРОВАТЬ ВЫДЕЛЕННОЕ`, `КОПИРОВАТЬ ВСЁ`,
  `СОХРАНИТЬ TXT (UTF-8)`. Панель рисует не больше `RESULT_PREVIEW_CHARS`
  (200 000) символов и говорит, сколько показано: вставка мегабайтов в Tk — это
  многосекундный проход отрисовки на Aqua. «Копировать всё» и экспорт TXT
  работают с расшифрованными данными: файл пишется байт в байт и сверяется по
  SHA-256 — ничего не нормализуется, ни один символ не заменяется, переводы строк
  не переписываются. Данные, не являющиеся корректным UTF-8, не «исправляются»,
  о них сообщается.
- `РАЗВЕРНУТЬ` открывает результат в окне на 80 % экрана: текст доступен для
  выделения и только для чтения, рядом `КОПИРОВАТЬ ТЕКСТ`, `ВЫДЕЛИТЬ ВСЁ`,
  `СОХРАНИТЬ TXT`, `КОПИРОВАТЬ ПУТЬ`, `ПОКАЗАТЬ В FINDER` (macOS `open -R`,
  Windows `explorer /select,`, Linux `xdg-open`) и `ЗАКРЫТЬ`; в окне лежит весь
  текст, даже если его собственная панель показывает предпросмотр.

### Размер окна, запуск и язык

Ничто в окне не задаётся константой, угаданной под один экран. Кнопка
измеряется своим шрифтом на текущем языке и получает эту ширину (явный `width=`
становится минимумом, а не потолком); ряд кнопок переносится на вторую строку,
вместо того чтобы уезжать за край карточки; `wraplength` абзаца следует за
шириной карточки. Поддерживаемые размеры — 980×720 (минимум), 1140×900,
1280×800, 1440×900 и развёрнутое окно — показывают все подписи на `en`, `ru` и
`uk`, и GUI-тесты проверяют это измерением каждой подписи после изменения размера
и после смены языка.

Запуск измеряется, а не обсуждается: `python tools/bench_startup.py` собирает всё
окно три раза и печатает медиану сборки, время первого кадра, число чтений списка
системных шрифтов и число созданных объектов шрифтов (`--stages` и `--profile`
показывают, куда уходит время); `PHANTOM_STARTUP_DEBUG=1` печатает по
строке на каждый этап (импорт, корень Tk, каждая вкладка, проходы отрисовки,
первый кадр, момент появления окна) и итоговую строку, а работа, которая не нужна
для первого кадра (журналирование, слежение за темой ОС), уходит в первый
холостой вызов цикла. Список шрифтов системы читается один раз на окно, а не на
каждый виджет, и сохранённая геометрия применяется до создания карточек — окно
раскладывается один раз в своём настоящем размере, а не дважды.

Предупреждения о ёмкости: выше 70 % битовый план статистически заметен, выше
90 % приложение предупреждает, что изменение слишком велико. Пороги — константы,
а не мнения, и они заведомо осторожные: `tools/bench_steganalysis.py` измеряет,
что они значат на практике. На восьми сгенерированных носителях 512×512
классические атаки χ² и RS не срабатывают ни при одной нагрузке, которую схема
может нести, — LSB matching сдвигает сэмплы на ±1 и оставляет гистограмму
нетронутой, а именно её эти детекторы и ищут. Строка `SIZE` считает по той же
арифметике: биты заголовка плюс восемь бит на каждый байт шифртекста, против
полезных бит носителя.

### Метаданные: что несёт файл и что с этим делать

Четвёртая вкладка (`МЕТАДАННЫЕ`) читает метаданные PNG, WAV или FLAC и предлагает
**выборочную** очистку. Всё локально: ни облака, ни API, ни телеметрии, ничего
никуда не отправляется.

Формат определяется по содержимому, а не по расширению: JPEG, переименованный в
`.png`, отклоняется, а не разбирается чужим парсером. Каждое поле показывается с
именем, значением, контейнером и одной из шести категорий — личные, описательные,
технические, права и авторство, происхождение и подписи, неизвестные — и одной из
трёх пометок: *можно удалить*, *защищено* или *производное* (значение, вычисленное
из других полей: координаты в десятичных градусах, свойства XMP-пакета).
Производная строка нужна, чтобы файл читался с одного взгляда; это не отдельная
запись, она не считается дважды, и удаление полей, из которых она построена,
убирает её вместе с ними.

- **Отмечены по умолчанию** личные поля, которые очистка умеет удалить:
  геопозиция, модель устройства, серийные номера, личные даты и комментарии.
- **Предлагаются, но не отмечены** поля авторства (EXIF `Artist`, PNG `Author`,
  RIFF `IART`, Vorbis `ARTIST`): имя — это личные данные, но удалять подпись
  автора или нет, решаете вы, поэтому флажок снят.
- **Блок удаляется целиком или не удаляется вовсе**: XMP-пакет, чанк iXML,
  встроенная картинка. Если в блоке есть что-то, что политика защищает — заголовок,
  строка о правах, — он помечается как *защищённый*, с причиной, вместо того чтобы
  предлагаться к удалению и падать на середине.
- **XMP читается, а не ищется по тексту.** Пакет разбирается как RDF/XML, поэтому
  свойство, записанное атрибутом `rdf:Description`, внутри `Bag`/`Seq`/`Alt`, во
  вложенном узле, под выбранным файлом префиксом или в пространстве имён, которого
  эта сборка не знает, остаётся свойством. Пакет, который не удаётся прочитать
  полностью — обрезанный XML, объявление DTD или сущности, слишком много элементов
  или вложенности, размер больше мегабайта, — считается защищённым, а не
  «наверное, безопасным»; несколько пакетов в одном файле оцениваются вместе.
  Свойства показываются по одному, поэтому «оставлен» никогда не значит
  «не показан».
- **Никогда не удаляются** строки копирайта и лицензии, технические параметры,
  цветовые профили, блоки происхождения и *неизвестные* чанки. Неизвестный чанк
  показывается как неизвестный и остаётся на месте: очистка не удаляет то, что не
  может объяснить.
- **Подписанный файл отклоняется.** Если найден манифест C2PA/JUMBF или блок
  подписи, вкладка сообщает об этом и блокирует очистку: перезапись контейнера
  нарушит жёсткую привязку манифеста, а «очищенный» файл, который всё ещё
  заявляет подпись, которой больше не соответствует, хуже бездействия. PHANTOM
  никогда не подделывает, не скрывает и не вырезает подпись, чтобы проверка
  прошла.

Перед записью показывается предочёт: что будет удалено, что останется и что вы
выбрали, но оно защищено. Очищенная копия — всегда **новый файл**: исходник не
изменяется, а путь, совпадающий с исходником, отклоняется.

Путь назначения вычисляется **после** определения реального формата: `photo.wav`
для PNG становится `photo.png`, и проверки на совпадение с исходником и на
существующий файл применяются именно к этому окончательному имени — с учётом
символических и жёстких ссылок. Если файл по этому пути уже есть, запись
отклоняется (`output_exists`), кроме случая, когда перезапись запрошена именно для
этого имени; имя, полученное заменой расширения, не перезаписывается никогда,
потому что пользователю его не показывали. В PHANTOM Desktop системный диалог
открывается заново уже с вычисленным путём: подтверждается ровно то, что будет
записано.

Публикация атомарна:
копия пишется во временный соседний файл, проверяется и только потом
переименовывается на место назначения; при любой ошибке временный файл удаляется,
а файл назначения остаётся нетронутым.

Проверка после очистки обязательна, а не рекомендательна:

- PNG: все пиксели (RGB/RGBA, включая альфу), размеры и CRC каждого чанка;
- WAV/FLAC: все PCM-сэмплы, битность, частоту, число каналов, число кадров и
  длительность, полное повторное декодирование;
- метаданные перечитываются, чтобы доказать: выбранные поля исчезли, защищённые
  остались;
- SHA-256 входа и выхода плюс отдельный SHA-256 **декодированного содержимого**.

Два хэша отвечают на два разных вопроса, и карточка целостности это объясняет:
**хэш всего файла меняется всегда**, потому что изменились байты метаданных, а
**хэш декодированного содержимого меняться не должен**, потому что сохраниться
должны пиксели и сэмплы. Если декодированное содержимое отличается, ничего не
публикуется.

Как читается вкладка сверху вниз: файл (с кнопкой **сбросить файл и результаты**),
то, что в нём есть (список полей — по две строки на поле: подпись сверху,
переносим­ое значение под ней, а защищённые строки приглушены и объяснены),
**план следующей операции**, куда сохранять, и **результат прошлой операции**.
План и результат — разные карточки, поэтому устаревший результат не может
выглядеть как свежий план. Кнопка сохранения недоступна, пока ничего не выбрано
или пока очистка заблокирована, и причина написана прямо под ней; если личных
полей в файле нет, вкладка пишет «Очистка не требуется» и объясняет, какие ещё
поля можно удалить; вердикт последней проверки выделен цветом, показывает число
полей до и после, а полные значения SHA-256 можно скопировать, а не только
16-символьный обрезок. Content credential показывается как «манифест обнаружен»
или «манифест найден, подпись не проверена» — но никогда как подтверждённая
подлинность.

Отчёт можно скопировать или экспортировать в TXT или JSON — в этом экспорте есть
личные значения, которые вы собирались удалить, поэтому он делается только по
явному требованию. Текстовый отчёт и все строки состояния идут на языке окна
(`en`/`ru`/`uk`, включая дисклеймер); JSON-экспорт остаётся английским и
версионированным, потому что его читает машина. Диагностика пишет количества, а не
значения.

Чего эта вкладка **не** делает: она не проверяет подпись C2PA (в этой сборке нет
ни списка доверия, ни цепочки сертификатов), она не удаляет данные, спрятанные в
пикселях или звуке помимо метаданных контейнера, и файл без найденных метаданных
не доказывает, что цифровых следов нет. Удаление метаданных — это не анонимизация.

## Ограничения

| Ограничение | Значение |
| --- | --- |
| Максимальный размер полезной нагрузки | 1 GiB |
| Максимальная длина имени файла | 8192 байта |
| Пароль | минимум 12 символов, генерируется 20, нормализация NFKC |
| Автоочистка буфера обмена | 30 секунд |
| Носители-изображения | только PNG, 1/2/4/8-бит, типы цвета 0/2/3/4/6, без APNG, без 16-бит |
| Носители-звук | WAV 8/16/24/32-бит, FLAC 16/24-бит |
| Звук с потерями | отклоняется (`.mp3 .aac .m4a .ogg .oga .opus .wma .mp2`) |

16-битные PNG отклоняются, а не обрезаются молча; 1/2/4-битные расширяются
до 8-бит без потерь и принимаются. Палитровые и монохромные изображения
конвертируются с уведомлением; прозрачность сохраняется, полностью прозрачные
пиксели никогда не используются как носители битов.

## Файлы старой версии 1

Файлы PHANTOM 1.x по-прежнему открываются: v1 писала нагрузку последовательным
LSB и PBKDF2-HMAC-SHA256 на 200000 итераций. Этот путь оставлен как ветка
только для чтения (`phantom.stego.legacy`) и проверяется эталонными фикстурами,
сгенерированными из исходного коммита, а не восстановленными по памяти. Новые
файлы всегда пишутся в формате v2.

## Затирание

«Затереть» перезаписывает файл один раз (`WIPE_PASSES = 1`, блоками по 1 MiB,
с `fsync` после каждого блока) и затем удаляет. На SSD, в copy-on-write ФС
(APFS, Btrfs, ZFS) и журналируемых ФС это **снижение риска, а не гарантия**:
контроллер накопителя может хранить старые копии. Приложение прямо говорит об
этом в диалоге подтверждения и не называет результат «безопасным стиранием».

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest -ra                 # весь набор
python -m pytest -m "not slow"       # без бенчмарков 24 МП
xvfb-run -a python -m pytest -m gui  # GUI-смоук на headless Linux
python -m pytest --cov=phantom --cov-branch --cov-report=term-missing
ruff check src tests tools
mypy src
```

Текущие цифры на Linux/Python 3.11: 844 headless-теста плюс 8 GUI-смоуков под
Xvfb и 98% покрытия строк и ветвей в `core`, `stego`, `audio` и `i18n`. Модули,
которым нужен Tk, проверяются задачей `gui`, поэтому прогон без дисплея
показывает по ним 0% — это ожидаемо, а не пробел в покрытии.

Тесты — страховочная сетка, а не украшение:

- `tests/test_no_stubs.py` ищет заглушки, молчаливые `except: pass` и
  запрещённые слова-обещания во всех модулях;
- тесты известных ответов фиксируют Argon2id, PBKDF2 и AES-GCM по
  опубликованным векторам;
- эталонные фикстуры v1 генерируются из исходного кода
  `tools/make_legacy_fixtures.py` и `tools/make_legacy_unicode_fixture.py`;
- тесты звука проверяют WAV/FLAC вторым декодером и убеждаются, что меняется
  только data-чанк;
- тесты утверждений безопасности проверяют, что каждое число в интерфейсе и в
  этом README берётся из `phantom.core.constants`.
