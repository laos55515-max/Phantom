# PHANTOM 2.0.0

Скрывает зашифрованные данные внутри PNG-изображения или аудиофайла WAV/FLAC и
извлекает их на другой машине по тому же паролю. Полезная нагрузка шифруется до
того, как в носитель записывается первый бит, и приложение не обещает больше,
чем реально делает код.

- Шифрование: **AES-256-GCM**, новая соль и nonce для каждой операции
- Ключ: **Argon2id · m=96 MiB · t=3 · p=1** (PBKDF2-HMAC-SHA256 с 600000
  итераций — отдельный профиль, который выбирают явно при встраивании; он не
  подставляется автоматически, если Argon2id недоступен: это была бы тихая
  деградация)
- Контейнер: версионированный, аутентифицированный, без magic-строки в открытом виде
- Интерфейс: CustomTkinter, три языка (Українська / Русский / English),
  темы Dark / Light / System, drag & drop
- Без сетевых вызовов, телеметрии и облака

`phantom.__version__ == "2.0.0"`, стадия: release candidate.

## Что это и чем это не является

Это **файловый контейнер в стеганографической оболочке**. Оболочка переживает
копирование, переименование и пересохранение файла без потерь. Она **не
переживает** ничего, что перекодирует медиа: экспорт в JPEG, режим «фото» в
мессенджере, транскодирование звука, изменение размера, обрезку или скриншот.
В мессенджерах отправляйте файл **как документ**.

LSB-стеганографию выявляют статистические детекторы. Приложение никогда не
утверждает, что нагрузку невозможно найти, — это было бы неправдой. Зато формат
не оставляет данных на известном месте: начиная с v3 позиции всех битов носителя,
включая зашифрованный заголовок, выводятся из пароля, поэтому без пароля читать
нечего, а неверный пароль неотличим от носителя без данных. Файлы, записанные в
раскладке v2 (заголовок на постоянных позициях), по-прежнему читаются. Сам факт
стеганографии — отдельный вопрос, и статистический анализ на него отвечает.

Модель угроз полностью описана в [`SECURITY.md`](SECURITY.md) (по-английски) и
в блоке «Что НЕ защищает» внутри приложения (на вашем языке).

## Требования

- Python 3.10+ (разработка на 3.11)
- Tk 8.6 для графического интерфейса (входит в сборки python.org для Windows и
  macOS; в Linux установите `python3-tk`)

## Установка

```bash
python -m venv .venv
. .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск

```bash
python app.py                   # из корня репозитория
python -m phantom               # после `pip install -e .`
```

Лаунчер добавляет `src/` в `sys.path`; для запуска из репозитория установка не нужна.

## Использование

1. Выберите носитель. PNG (1/2/4/8-бит, без анимации) для изображений; WAV
   (8/16/24/32-бит) или FLAC (16/24-бит) для звука. Форматы с потерями — MP3,
   AAC, M4A, OGG, OPUS, WMA — отклоняются сразу: транскодирование уничтожает данные.
2. Посмотрите строку ёмкости. Она равна `(usable_bits - 400) / 8 - 16` байт:
   400 бит на закрытый заголовок, 16 байт резервируются под тег GCM. «Полезные
   биты» — это один бит на цветовой канал каждого полностью непрозрачного
   пикселя либо один бит на канал каждого сэмпла звука.
3. Введите секрет или выберите файл. Текст сжимается, файл сохраняет имя; и то и
   другое хешируется SHA-256 и аутентифицируется.
4. Введите пароль не короче 12 символов. Похожие внешне Unicode-пароли
   нормализуются по NFKC, поэтому пароль, набранный в другой раскладке, всё равно
   откроет файл. Можно сгенерировать пароль из 20 символов.
5. Сохраните. Приложение пишет во временный файл, перечитывает его, извлекает
   данные обратно и сравнивает SHA-256 **до** того, как готовая копия заменит
   целевой файл. Если проверка не прошла, ничего не публикуется.
6. Для извлечения откройте носитель, введите пароль и сохраните текст или файл.
   Имена выходных файлов очищаются, расширение принудительно выставляется.

### Редактирование, прокрутка и чтение результата

Текстовые поля ведут себя как нативные на всех платформах:

- `Cmd+C/V/X/A` на macOS, `Ctrl+C/V/X/A` в остальных системах, плюс меню по
  правому клику (двумя пальцами) со пунктами «Вставить», «Копировать»,
  «Вырезать», «Выделить всё». Каждое сочетание вешается на внутренний Tk-виджет,
  поэтому прокси CustomTkinter его не проглатывает.
- Кнопки `ВСТАВИТЬ` и `КОПИРОВАТЬ КЛЮЧ` рядом с обоими полями пароля — на случай,
  когда системное сочетание до приложения не доходит.
- Колесо мыши и трекпад прокручивают всю вкладку, а не только ползунок: событие
  поднимается от любого дочернего виджета к своей прокручиваемой области
  (дельты macOS инвертированы и не округляются в ноль). Текстовое поле оставляет
  колесо себе, пока может прокручиваться само.
- `РАЗВЕРНУТЬ` открывает результат в окне на 80 % экрана: текст доступен для
  выделения и только для чтения, рядом `КОПИРОВАТЬ ТЕКСТ`, `КОПИРОВАТЬ ПУТЬ`,
  `ПОКАЗАТЬ В FINDER` (macOS `open -R`, Windows `explorer /select,`,
  Linux `xdg-open`) и `ЗАКРЫТЬ`.

Предупреждения о ёмкости: выше 70 % битовый план статистически заметен, выше
90 % приложение предупреждает, что изменение слишком велико. Пороги — константы,
а не мнения.

## Ограничения

| Ограничение | Значение |
| --- | --- |
| Максимальный размер полезной нагрузки | 1 GiB |
| Максимальная длина имени файла | 8192 байта |
| Пароль | минимум 12 символов, генерируется 20, нормализация NFKC |
| Автоочистка буфера обмена | 30 секунд |
| Носители-изображения | только PNG, 1/2/4/8-бит, типы цвета 0/2/3/4/6, без APNG, без 16-бит |
| Носители-звук | WAV 8/16/24/32-бит, FLAC 16/24-бит |
| Звук с потерями | отклоняется (`.mp3 .aac .m4a .ogg .oga .opus .wma .mp2`) |

16-битные PNG отклоняются, а не обрезаются молча; 1/2/4-битные расширяются
до 8-бит без потерь и принимаются. Палитровые и монохромные изображения
конвертируются с уведомлением; прозрачность сохраняется, полностью прозрачные
пиксели никогда не используются как носители битов.

## Файлы старой версии 1

Файлы PHANTOM 1.x по-прежнему открываются: v1 писала нагрузку последовательным
LSB и PBKDF2-HMAC-SHA256 на 200000 итераций. Этот путь оставлен как ветка
только для чтения (`phantom.stego.legacy`) и проверяется эталонными фикстурами,
сгенерированными из исходного коммита, а не восстановленными по памяти. Новые
файлы всегда пишутся в формате v2.

## Затирание

«Затереть» перезаписывает файл один раз (`WIPE_PASSES = 1`, блоками по 1 MiB,
с `fsync` после каждого блока) и затем удаляет. На SSD, в copy-on-write ФС
(APFS, Btrfs, ZFS) и журналируемых ФС это **снижение риска, а не гарантия**:
контроллер накопителя может хранить старые копии. Приложение прямо говорит об
этом в диалоге подтверждения и не называет результат «безопасным стиранием».

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest -ra                 # весь набор
python -m pytest -m "not slow"       # без бенчмарков 24 МП
xvfb-run -a python -m pytest -m gui  # GUI-смоук на headless Linux
python -m pytest --cov=phantom --cov-branch --cov-report=term-missing
ruff check src tests tools
mypy src
```

Текущие цифры на Linux/Python 3.11: 844 headless-теста плюс 8 GUI-смоуков под
Xvfb и 98% покрытия строк и ветвей в `core`, `stego`, `audio` и `i18n`. Модули,
которым нужен Tk, проверяются задачей `gui`, поэтому прогон без дисплея
показывает по ним 0% — это ожидаемо, а не пробел в покрытии.

Тесты — страховочная сетка, а не украшение:

- `tests/test_no_stubs.py` ищет заглушки, молчаливые `except: pass` и
  запрещённые слова-обещания во всех модулях;
- тесты известных ответов фиксируют Argon2id, PBKDF2 и AES-GCM по
  опубликованным векторам;
- эталонные фикстуры v1 генерируются из исходного кода
  `tools/make_legacy_fixtures.py` и `tools/make_legacy_unicode_fixture.py`;
- тесты звука проверяют WAV/FLAC вторым декодером и убеждаются, что меняется
  только data-чанк;
- тесты утверждений безопасности проверяют, что каждое число в интерфейсе и в
  этом README берётся из `phantom.core.constants`.
